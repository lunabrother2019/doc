1. 论文原理

1.1 核心问题

把 Stanford Smallville (Generative Agents, Park et al. 2023) 的 Profile / Memory / Reflection / Action 架构搬到推荐场景：每个真实 MovieLens-1M 用户变成一个 LLM Agent，在翻页式推荐中自主决定 看不看 / 评几分 / 是否退出。

核心验证：LLM 模拟的用户行为分布能否与真实人群一致？如果能 → LLM Agent 可替代真人做离线 A/B 测试。
验证方法：Kolmogorov-Smirnov 检验，比较模拟评分分布与真实评分分布的最大 CDF 偏差。

1.2 三维 Social Trait（论文最核心的设计）

每个 Agent 有三维 trait，每维 3 档，共 3×3×3 = 27 个 prototype 覆盖 1000 用户：

Activity (活跃度)

决定翻几页才退出

  1. Elusive — 稍不满就走
  2. Occasional — 有几次不满就走
  3. Enthusiast — 很有耐心不轻易走
Conformity (从众度)

评分是否跟随历史均分

  1. Follower — 紧跟历史评分
  2. Balanced — 兼顾历史和自己
  3. Maverick — 完全按自己口味
Diversity (多样性)

口味宽窄

  1. Selective — 极度挑剔
  2. Niche Explorer — 偶尔探索
  3. Trailblazer — 来者不拒

关键设计：行为后果直接硬编进 persona prompt。不靠复杂 reflection 链来"涌现"退出行为，而是 prompt 里明确说 "you will exit the recommender system immediately even if you just feel little unsatisfied"。这是 Agent4Rec 控制成本和确定性的核心手法。

1.3 每页交互流程

推荐器 (LightGCN)
  │  每页推荐 4 部电影（title + history rating + summary）
  ↓
Avatar (LLM Agent) ──→ 一次 LLM 调用，输出三段式结构化回答：
  │
  ├─ (1) ALIGN 判定（对每部电影）
  │     MOVIE: Babe (1995);          ALIGN: yes; REASON: 动画+冒险,符合偏好
  │     MOVIE: Groundhog Day (1993); ALIGN: no;  REASON: 不在我的偏好类型里
  │
  ├─ (2) WATCH 选择（基于 activity + diversity trait）
  │     NUM: 3; WATCH: Babe, Aladdin, Shakespeare in Love
  │
  └─ (3) RATING + FEELING
        MOVIE: Babe;               RATING: 4; FEELING: charming and delightful
        MOVIE: Shakespeare in Love; RATING: 5; FEELING: perfect blend of romance
  │
  ↓
Memory 写入 → Reflection 触发 (每 3 条 memory)
  │
  ├─ [satisfied]   → [NEXT PAGE] 继续翻页
  └─ [unsatisfied] → [EXIT] 退出

1.4 与 Smallville 的关系

Smallville 概念Agent4Rec 对应简化程度
Memory StreamFAISS VectorStore + LangChain保留 relevance，旁路 recency/importance
Reflection每 3 条 memory 触发满意度评估简化为 satisfied/unsatisfied 二分
Planning无完全省略（推荐场景不需要长期规划）
ActionALIGN / WATCH / RATING / EXIT结构化输出，单次 LLM 调用
Persona3×3×3 = 27 trait prototype硬编码行为后果，不靠涌现

2.2 关键模块详解

Arena (simulation/arena.py)

仿真总控。管理推荐列表生成（LightGCN 预排序 → 分页）、avatar 并发调度、行为收集。

  • page_generator() — 从 LightGCN 全量排序中按页切分 top-K 电影
  • async_simulate_one_avatar() — 并发模式，每个 avatar 独立线程
  • simulate_one_avatar() — 串行模式，逐 avatar 逐页执行
  • parse_response() — 正则解析 LLM 结构化输出（ALIGN/WATCH/RATING/EXIT）

Avatar (simulation/avatar.py)

单个用户 Agent。初始化 3 维 trait → 构建 persona prompt → 管理 memory → 调用 LLM → 解析行为。

  • Trait dict 硬编码 3×3×3 的 persona 描述文本
  • Embedding 使用类级单例 Avatar._shared_embeddings（优化：1000 avatar 共享一个模型实例）
  • 每次 LLM 调用带 retry + exponential backoff

Memory (simulation/memory.py)

基于 LangChain 的 BaseMemory，核心是 FAISS 向量存储。

  • reflection_threshold=3 — 每 3 条新记忆触发一次满意度反思
  • 反思结果是 [satisfied] / [unsatisfied] + 原因文本
  • 注意：Smallville 原版的 recency + importance 权重被旁路，实际只用 relevance

4. 实验结果：KS 检验与 Prompt 校准

4.1 KS 检验全景对比

KS-D (Kolmogorov-Smirnov 距离)：模拟评分 CDF 与真实评分 CDF 的最大偏差。越小越好，D < 0.05 通常认为"无显著差异"。

版本N1★2★3★4★5★KS-DMean
Real (MovieLens)185,660 5.8%10.8%26.1%34.8%22.5% —3.575
plus_full (未校准)4,052 0.0%0.0%3.8%52.4%43.7% 0.3894.399
calibrated_v1508 17.3%24.8%3.5%17.5%36.8% 0.2553.317
calibrated_v2508 0.0%27.0%12.8%20.7%39.6% 0.1713.728
calibrated_v3520 0.0%19.4%18.5%29.0%33.1% 0.1063.758
calibrated_v3_full2,068 0.0%22.6%27.4%22.6%27.4% 0.0763.547

4.2 校准历程分析

plus_full → v3_full：KS-D 从 0.389 降到 0.076（-80%）
核心手段是在 prompt 中逐步引导 Agent 给出更真实的评分分布。从"全是 4-5 星的 utopian bias"逐步校准到接近真实的 2-3-4-5 分布。
v3_full 的均值 3.547 几乎等于真实的 3.575（差 0.03）
2-5 星分布已经非常接近真实。KS-D = 0.076 距离"统计无显著差异"阈值（0.05）很近。
唯一遗留问题：1★ = 0%（真实是 5.8%）
经过 4 轮 prompt 校准，LLM 仍然不愿意打 1 星。这是 OmniBehavior (2026) 论文定义的 utopian bias 的最后堡垒——LLM 的"善良本能"让它不给任何电影最低分。v1 曾短暂出现 17.3% 的 1 星，但那是过度校准导致的（2 星也飙到 24.8%），后续版本未能精确控制。

4.3 关键发现

  1. 更强模型不能修复结构性偏差 — 论文用 GPT-3.5 报告 KS 通过；GLM-4-plus（更强）跑出 D=0.39，说明模型能力不是瓶颈，prompt 设计才是。
  2. Prompt 校准的投入产出极高 — 4 轮校准（plus_full → v1 → v2 → v3 → v3_full），KS-D 降 80%，成本几乎为零（只改 prompt 文本）。
  3. 分布均值比分布形状更容易对齐 — v3_full 均值差只有 0.03，但 1★ 缺失导致 KS-D 仍有 0.076。
  4. 519/1000 用户产生了行为 — 约一半 avatar 在所有页面都没看电影（activity=1 的 Elusive 用户直接退出）。这本身是一个有趣的仿真发现。

5. P3 反馈闭环实验

5.1 实验设计

Round 0: LightGCN(原始) → 100 avatars 仿真 → 收集评分
                                                 ↓
Round 1: 评分注入 train.txt → 重训 LightGCN → 仿真 → 收集评分
                                                 ↓
Round 2: 评分注入 train.txt → 重训 LightGCN → 仿真 → 收集评分
                                                 ↓
Round 3-4: ... 重复 ...
                                                 ↓
每轮计算 KL(模拟分布 || 真实分布)，观察趋势

核心问题：当 Agent 的行为被反馈回推荐器再训练，系统是收敛、发散还是振荡？

5.2 结果

Round评分数活跃用户均值4-5★ 占比KL(sim‖real)
0 (baseline)————0.189
1282264.56798.2%0.560

结论：振荡，既不收敛也不发散
KL 在 0.55-0.61 之间反复波动，4 轮没有明显趋势。活跃用户数稳定在 25-32。这对应 recsys-code-plan 中 P3 的"有条件收敛"场景。
注意：P3 用的是未校准 prompt
闭环实验中 avatar 的评分 98%+ 是 4-5 星（utopian bias），而 v3_full 的校准 prompt 尚未应用到闭环实验。用校准后的 prompt 重跑可能得到不同结论。

7. TODO：下一步验证什么

1
修复 1★ 缺失 优先级最高 · 投入小

v3_full 的 2-5 星已经很好，但 1★=0%。在 prompt 中加入"如果电影完全不符合你的口味或品质极差，给 1 分"的显式指令。如果成功 → KS-D 从 0.076 降到 ~0.05，达到统计无显著差异阈值。

2
P3 闭环用校准 prompt 重跑 + 扩到 10+ 轮

当前 P3 的 KL=0.55-0.61 是因为 avatar 用了未校准 prompt（98% 是 4-5 星），注入这些高分后推荐器会偏向推荐更多高分电影 → 正反馈循环。换成 v3 校准 prompt 后，分布更真实，闭环可能出现不同趋势。同时从 4 轮扩到 10-15 轮看长期行为。

3
Memory 消融：有/无 memory 对 KS-D 的影响

关闭 FAISS memory + reflection，只靠 trait prompt。如果 KS-D 恶化 → memory 对仿真保真度有正贡献（可写 paper）。如果不变 → memory 在推荐场景没用（也值得报告）。

4
LightGCN vs MF 推荐器对比

用相同的 calibrated_v3 prompt，分别在 LightGCN 和 MF 上跑。如果不同推荐器下 agent 行为差异大 → 说明仿真对推荐算法敏感（重要发现）。MF 的 100 user behavior pkl 已在 storage/ 里。

5
与 TriRec / AFL 交叉对比

三个复现项目形成三角对比：Agent4Rec（用户仿真保真度）× TriRec（三方博弈公平性）× AFL（双 Agent 反馈闭环）。在同一数据集（MovieLens）上对比不同架构的 agent 行为差异。

6
calibrated_v3_full 补完 1000 avatar

当前只跑了 519/1000（进程卡死在 20 小时处）。修复卡死原因（可能是 API timeout 在并发模式下的死锁），补完剩余 481 个 avatar，得到完整的 1000 人 KS 检验。
