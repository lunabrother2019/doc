目标定义

核心目标
构建一个可验证的 Agent 仿真系统：Agent 的行为能与真实数据做定量对比（KS 检验 / 分布对齐），而不仅仅是"看起来像"。
需要确定的关键问题：
  1. 仿真什么场景？ 社会行为（小镇式）/ 推荐消费 / 游戏经济 / 专业领域？
  2. 目标规模？ 25-100（深认知原型）/ 1K-10K（中等）/ 100K+（统计意义）？
  3. 有没有可对标的真实数据？ 这决定了能否做验证——没有真实数据的仿真只是"讲故事"。
  4. 是做研究（发论文）还是做产品（工程落地）？ 前者追求新意，后者追求稳定。
  5. LLM 预算？ 纯 API（贵但简单）/ 本地模型（需 GPU 但长期便宜）/ 混合？

关键设计原则（来自 64 篇的教训）
  • Memory 是 ADD-only — Mem0 V3 实测证明 LLM 做 UPDATE/DELETE 会误删有效记忆（LoCoMo 71.4→91.6）
  • Reflection 需要外部信号 — Self-Correct (DD28) 证明无外部 oracle 的自我反思无效
  • 规模和认知深度是 tradeoff — OASIS 百万 Agent 无记忆 vs 小镇 25 Agent 深记忆，目前无法两全
  • 验证决定可信度 — 没有验证的仿真是"讲故事"，有验证的仿真才是"做科学"

四阶段实施计划

P1 理解核心架构 ~2 周

目标：跑通小镇 + Concordia，理解 Memory/Reflection/Planning 的数据流。

克隆小镇仓库 joonspk-research/generative_agents，本地跑通 ✅ 已完成 · 路径: /opt/workspace/hehe/agentic_collab
阅读 memory_stream.py，理解 recency×importance×relevance 三维公式
阅读 reflection.py，理解 importance 累计触发 → LLM 合成 insight
阅读 plan.py，理解日→小时→分钟的层级分解
pip install concordia，跑官方 example
理解 Concordia 的 Entity×Component×Engine 设计模式
写对比笔记：小镇的直接实现 vs Concordia 的 ECS 模块化，各自优缺点
P1 结束时的决策点：选择基础框架。小镇代码适合快速原型，Concordia 适合模块化扩展。如果你的仿真场景和小镇差异大（比如推荐系统），Concordia 的 ECS 更容易适配。
P2 构建仿真场景 ~2 周

目标：用选定框架搭建你自己的仿真场景，Agent 能在环境中执行基本行为。

定义 Entity：Agent 的 persona 数据结构（demographics + traits + backstory）
定义 Environment：仿真世界的状态空间 + 可执行动作 + 观察接口
实现 Agent Loop：Perceive → Retrieve → Plan → Act 主循环
实现基础 Memory：至少支持 add() + search() + get_all()
跑通 2-5 个 Agent 的最小仿真
确认 Agent 行为"看起来合理"（定性验证）
P2 关键设计决策：
  1. Persona 从哪来？手写（小镇式）/ 真实数据初始化（RecAgent/SocioVerse 式）/ LLM 生成？
  2. Memory 后端选什么？内存列表（原型）/ SQLite（轻量持久化）/ Mem0 SDK（生产级）？
  3. LLM 调用怎么管理？直接 API / LangGraph 编排 / MCP 协议？
P3 加记忆深度 + 验证 ~2 周

目标：给 Agent 加 reflection + 三信号检索，并建立验证 pipeline。

实现 Reflection 触发器（importance 累计 or emotion-driven）
实现三信号检索：semantic + BM25 + entity boost（参考 Mem0 V3 DD30）
实现 Agent 间社交通信（对话生成 + 信息传播）
找到可对标的真实数据集
实现验证 pipeline：Agent 行为分布 vs 真实数据的 KS 检验
跑验证，记录差距，分析原因
P3 的"记忆压缩"实验（ALCS 启发）：
  1. 给每条 reflection 摘要加一个"压缩损失"分数（简化版 Hessian）
  2. 当分数低于阈值时，自动回溯 raw memory 而非使用摘要
  3. 这是一个研究空白——目前没有任何系统做过（DD64 分析）
P4 规模化 + 优化 持续

目标：从 5 Agent 扩展到目标规模，优化成本和延迟。

如果 >100 Agent：实现 prompt cache 共享（参考 Agent4Rec $16/1000人）
如果 >1K Agent：实现异步调度 + batch LLM 调用（参考 OpenCity DD35）
如果 >10K Agent：SFT 蒸馏到本地 7B 模型（参考 FireAct/AgentTuning DD61）
如果 >100K Agent：activation probability 控制活跃比例（参考 OASIS DD55）
因果干预实验：改变条件 → 观察仿真结果变化 → 对比真实数据
A/B 等价验证（终极目标）：仿真结论 vs 真实 A/B 测试一致性
规模化的成本模型：
25 Agent~$5/次运行直接 API
1K Agent~$16-50/次prompt cache + batch
10K Agent~$200-500/次需要本地模型或 SFT
100K+ Agent需要本地 GPU 集群SFT 7B + activation sampling

记忆系统设计（核心中的核心）

基于 64 篇 deep-dive 的记忆系统最佳实践汇总：

记忆写入策略

策略代表优点缺点实测数据
ADD-only + hash 去重Mem0 V3不会误删有效记忆冗余增长LoCoMo 71.4→91.6
ADD/UPDATE/DELETEMem0 论文版存储更紧凑LLM 误删风险高LoCoMo 71.4
Append-only + recency decay小镇原版最简单无去重—

建议：用 ADD-only + hash 去重（Mem0 V3 已验证）。

记忆检索策略

策略代表信号
三维加权公式小镇0.5·recency + 0.3·importance + 0.2·relevance
三信号融合Mem0 V3semantic + BM25 + entity boost
可学习检索ACAN (DD26)Cross-Attention 神经网络替代手调

记忆压缩（研究空白）

ALCS (DD64) 揭示的三个空白
  1. 压缩损失度量 — 给 reflection 摘要标注"这条摘要丢了多少信息"
  2. 回溯诊断 — 当摘要不可信时自动回溯 raw memory
  3. 最优遗忘 — Bayesian 框架下的最优遗忘速率（替代 ad-hoc 的 exponential decay）

验证方案（不可跳过）

没有验证的仿真 = 讲故事

这是 challenge/validation-gap.html 的核心论点：Agent 仿真要成为"科学"而非"艺术"，必须有可量化的验证。

四级验证体系

L1
行为分布对齐（最低标准）— Agent 群体行为统计分布 vs 真实数据（KS 检验）
参考：Agent4Rec 评分分布 KS 通过
L2
社会现象涌现（中等标准）— 信息茧房 / 从众 / 极化是否自然出现
参考：RecAgent 信息茧房 + OASIS 群体极化
L3
因果干预响应（高标准）— 改变条件后仿真结果是否合理变化
参考：Beyond Playtesting 黑市干预 27.4%→1.5%
L4
A/B 等价（终极目标，尚无人达到）— 仿真结论 vs 真实 A/B 测试一致
参考：RecoWorld (DD59) 正在尝试但是 position paper

最适合验证的领域

领域Ground Truth 密度反馈速度评估指标成熟度综合可行性
推荐系统极高（点击/购买日志）秒级极成熟（NDCG/Recall）最高
游戏/MMO高（服务器日志）分钟级中等高
社交媒体中（公开帖子）小时级中等中
社会行为低（调查数据）月级低低

风险与待讨论

技术风险

风险影响缓解
LLM 行为偏差（善良偏差/位置偏差）Agent 行为系统性偏离真人Agent4Rec 已发现低评分偏少；需要 debias
记忆爆炸（长期运行）上下文溢出 / 检索变慢ADD-only + 定期 compaction
规模成本失控实验跑不起先小规模验证，确认有效再扩大
Reflection 质量不可控合成的 insight 可能是幻觉加压缩损失度量（ALCS 启发）
框架锁定换框架成本高模块化设计，memory/reflection/planning 可独立替换

开放讨论项

  1. 认知分层策略：是否给不同 Agent 不同的认知深度？"主角"有完整记忆+反思，"路人"只有规则？这和游戏中 LOD (Level of Detail) 思想类似。
  2. 时间模型：仿真中的"一天"对应现实多长时间？小镇是 1:1 实时（太慢），SocioVerse 是一次性问卷（太简单），需要找到中间点。
  3. 涌现 vs 可控：Ubisoft Teammates 用行为树约束 Agent（可控但无惊喜），小镇完全自主（有惊喜但不可控）。仿真需要哪种？
  4. 多模型 vs 单模型：oh-my-openagent 式的多模型路由在仿真中有意义吗？比如"主角 Agent 用 Opus，背景 Agent 用 Haiku"？
  5. 数据隐私：如果用真实用户数据初始化 persona（SocioVerse 式），隐私合规怎么处理？
