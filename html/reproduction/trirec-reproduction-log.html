1. 论文解读：TriRec 三方代理推荐

1.1 核心问题

传统推荐系统只考虑 用户偏好（user-centric）：给用户推最想看的东西。但推荐是一个三方博弈：

参与方诉求传统系统中的地位
User (用户)看到自己喜欢的内容核心优化目标
Item (物品/商家)获得曝光、触达目标用户被动等待被推荐
Platform (平台)生态公平、长期健康隐式硬编码规则

TriRec 的创新：让三方都成为有自主能力的 LLM Agent，各自有记忆、有策略、能博弈。

Stage 1 — Item Promotion + User Evaluation

Item Agent 拿到用户画像后，为自己（物品）写一段个性化推广文案，突出最匹配该用户口味的卖点。User Agent 阅读所有候选物品的推广文案，结合自己的历史偏好，逐个打分 1-5 分。

关键洞察：Item Agent 的推广不是无差别广告，而是针对每个用户定制的——同一张专辑对爵士爱好者和摇滚爱好者说的话不同。

Stage 2 — Platform Multi-Objective Rerank

Platform Agent 拿到 User 打分后，不是简单按分数排序，而是用多目标贪心算法逐位选择：

  • 高排位 (pos 1-3)：权重偏向相关性（用户满意度优先）
  • 低排位 (pos 7-10)：权重偏向公平性（给少曝光类别机会）
  • 位置权重公式：alpha_k = 1 / (1 + 0.3 × pos)

1.3 与 Generative Agents 的关系

TriRec 把 Smallville 的 Agent 架构（记忆 + 反思 + 行动）具象化到推荐场景：

Smallville 概念TriRec 对应
Memory StreamUserMemory (交互历史) / ItemMemory (物品属性)
Reflection → ProfileLLM 从历史交互中生成用户偏好画像
PlanningItem Agent 制定个性化推广策略
Action & InteractionStage 1 的 Item↔User 交互 + Stage 2 的 Platform 调控
Multi-Agent Dynamics三方（User/Item/Platform）各自优化不同目标

2. 指标详解：看懂实验结果

2.1 准确率指标 (越高越好)

NDCG@K — Normalized Discounted Cumulative Gain

一句话：推荐列表前 K 个结果的排序质量。不仅看推没推对，还看推对的排在第几位。

DCG@K = Σi=1..K rel(i) / log₂(i+1)
NDCG@K = DCG@K / IDCG@K

直觉：用户喜欢的物品排在第 1 位得 1.0 分，排在第 2 位得 0.63 分，排在第 5 位只得 0.39 分。排位越靠前贡献越大（对数衰减）。最后除以"理想排序"得到归一化分数。

实验中：NDCG@5 = 0.0545 意味着平均而言，每个用户的 top-5 推荐列表达到了理想排序质量的 5.45%。数字不高，因为我们用的是合成数据 + 只有 1 个正例。

Hit@K — 命中率

一句话：前 K 个推荐中有没有至少命中 1 个用户真正喜欢的物品。

Hit@K = (命中用户数) / (总用户数)

直觉：最简单粗暴的指标——推荐列表前 5 个里有没有用户喜欢的东西？有 = 1，没有 = 0，所有用户取平均。

实验中：Hit@5 = 0.10 意味着 50 个用户中有 5 个人在 top-5 里看到了自己测试集中喜欢的物品。

MRR — Mean Reciprocal Rank

一句话：正确答案排在第几位的倒数，所有用户取平均。

MRR = (1/N) × Σ 1/ranki

直觉：正确物品排第 1 得 1.0 分，排第 2 得 0.5 分，排第 10 得 0.1 分，没出现得 0 分。关注的是"第一个正确答案出现得多快"。

2.2 公平性指标 (越低越好)

DGU@K — Distributional Group Unfairness

一句话：不同物品类别（如 Rock/Jazz/Pop）在推荐列表中的曝光分布与理想均匀分布的偏差。

DGU@K = (1/G) × Σg |actual_share(g) − ideal_share(g)|
其中 ideal_share = 1/G (G=类别数), actual_share 按位置加权曝光

直觉：假设有 10 个音乐流派，理想情况每个流派占 10% 曝光。如果 Rock 占了 50%、Jazz 占 0%，DGU 就很高。DGU 衡量的是平均不公平程度。

实验中：DGU@10 从 0.029 降到 0.019，说明 TriRec 让各类别曝光更均匀了。

MGU@K — Maximal Group Unfairness

一句话：与 DGU 类似，但只看最不公平的那一组——被压制最严重或垄断最厉害的类别。

MGU@K = maxg |actual_share(g) − ideal_share(g)|

直觉：DGU 是所有类别不公平的平均值，MGU 是最大值。比如 10 个类别中 9 个分布均匀，但 Hip-Hop 完全没曝光——DGU 可能不高，但 MGU 会很高。MGU 抓的是最极端的不公平。

实验中：MGU@10 从 0.066 降到 0.040，最受压制的类别也改善了。

EIU@K — Expected Item Utility

一句话：所有出现过的物品获得的平均曝光价值。衡量曝光是集中在少数热门物品还是分散给更多物品。

EIU@K = (1/|出现物品数|) × Σitem Σpos 1/log₂(pos+2)

直觉：如果只有 10 个物品反复出现在所有用户的推荐列表里，每个物品平均曝光很高 → EIU 高。如果 200 个物品都有机会出现，平均曝光就低 → EIU 低。EIU 下降说明曝光更分散（更多物品有机会），这是公平性提升的信号。

实验中：EIU 从 1.067 降到 0.817，说明 TriRec 让更多物品获得了曝光。

2.3 指标间的关系

传统零和假设：提升准确率(NDCG/Hit) → 推热门物品 → 冷门类别曝光减少 → 公平性(DGU/MGU)恶化
TriRec 的突破：三方 Agent 博弈后，准确率和公平性同时提升。关键在于 Item Agent 的个性化推广让冷门物品也能找到目标用户（而非让所有人看热门物品）。

3.2 三个 Agent 详解

Item Agent — 物品自我推广

文件：agents/item_agent.py

做什么：对每个 (物品, 目标用户) 组合，生成 2-3 句个性化推广文案。

输入：物品元数据 + 物品自我介绍 + 用户偏好画像

输出：一段推广文字（如 "This jazz album features smooth saxophone solos that match your preference for relaxing evening music"）

API 调用：每个候选物品 1 次 → 50 候选 × 50 用户 = 2500 次（有缓存）

prompt = f"""You are a product promotion agent.
[Product Information] {item_text}
[Product Self-Description] {item_memory.description}
[Target User Profile] {user_profile}
Write a short personalized promotion (2-3 sentences)..."""
User Agent — 用户候选评估

文件：agents/user_agent.py

做什么：阅读候选物品的推广文案，批量打分 1-5。

输入：用户画像 + 近期历史 + 候选物品列表（每批 10 个）

输出：{item_id: score}，score ∈ {1,2,3,4,5}

解析策略：正则匹配 ID=item_xxx SCORE=N，未匹配的默认 3 分（中性）

API 调用：50 候选 / 10 每批 = 5 次/用户 → 250 次（有缓存）

Platform Agent — 多目标重排序

文件：agents/platform_agent.py

做什么：不用 LLM，纯算法实现逐位贪心重排。

核心公式：

score(item, pos) = αk × relevance + (1 − αk) × (0.6 × fairness + 0.4 × item_utility)

αk = 1 / (1 + 0.3 × pos)   ← 高位重相关性，低位重公平
relevance = 0.7 × (user_score/5) + 0.3 × cosine_sim   ← LLM 打分 + embedding 相似度混合
fairness = 1 − DGU(当前已选列表 ∪ {item})   ← 加入后类别分布越均匀，得分越高
item_utility = CTR(pos) × exposure_bonus   ← 历史少曝光的物品获得加成

逐位贪心：每个位置独立选最优物品。位置 0 的 α0=1.0（纯相关性），位置 9 的 α9=0.23（大部分权重给公平性）。这就是为什么 Stage 2 在不损失准确率的前提下提升了公平性。

4.2 关键发现

发现 1：Item Promotion 是准确率提升的主要来源
Hit@5 从 6% → 10% (+66.7%)，NDCG@5 从 0.041 → 0.054 (+30%)。Item Agent 的个性化推广帮助 User Agent 更准确地识别匹配偏好的物品。Stage 2 没有进一步提升准确率——它的任务不是提升准确率，而是在保持准确率的前提下注入公平性。
发现 2：Platform Rerank 主要贡献公平性
DGU 从 0.022 → 0.019 (额外 −12%)，MGU 从 0.042 → 0.040 (额外 −6%)。同时 NDCG/Hit 保持不变。这符合论文设计：Platform Agent 用位置权重衰减 (αk) 在不损害头部排位准确性的前提下，在尾部位置注入公平性。
发现 3：EIU 下降是预期行为
EIU 衡量"平均每个物品获得多少曝光"。TriRec 让更多物品出现在推荐列表中（曝光更分散），所以每个物品的平均曝光降低了。这是公平性提升的自然结果。
核心结论验证：精度和公平性可同时提升
Baseline → Full TriRec：NDCG +32%、Hit +67%、DGU −34%、MGU −40%。打破了传统"精度 vs 公平"的零和假设。三方 Agent 博弈让系统找到了帕累托改进。

6.2 当前数据的局限

核心局限：合成数据
当前实验用的是 loader.py::_generate_demo_data() 生成的合成数据：随机生成 300 个物品（10 个流派 × 30 专辑），50 个用户各有 1-3 个偏好流派。这意味着：
  • 物品描述是模板化的（"A jazz album by Artist_X. Features N tracks..."）
  • 用户偏好是硬编码的（偏好流派内的物品一定高分）
  • 绝对数值（NDCG=0.05）没有论文可比性，只有趋势（TriRec > Baseline）有效
要产出有说服力的结果，必须接入真实数据集。

7. 后续路线图

1
接入真实数据集 — Amazon CDs & Vinyl 优先级最高

替换合成数据为真实评分数据。loader.py 已预留了 download_amazon_cds() 函数框架，需要：(1) 下载 Amazon CDs & Vinyl 数据集；(2) 解析 ratings + metadata；(3) 按用户交互数筛选活跃用户；(4) 重跑三组对照。这是从"demo 验证"到"可信实验"的关键一步。

2
异步并发 GLM 调用

当前串行调用：每个 API 3-5秒，50用户共 ~2750 次调用 ≈ 56 分钟。用 asyncio + aiohttp 改为并发 10 路，预计 5-10 分钟完成。这是扩大规模的前置条件。

3
消融实验

验证每个组件的独立贡献：(a) 只跑 Stage2 不跑 Stage1；(b) 调 αk 的衰减速率；(c) 候选集 20/50/100 对比；(d) 不同 batch_eval_size 对 User 打分的影响。

4
GLM-4-plus / 更强模型对比

用更强的模型看 Item promotion 质量和 User evaluation 准确度是否提升。可以和之前 AFL 实验中 GLM-4-flash vs GLM-4-plus 的结论做交叉对比。

5
扩大到 200-2000 用户

在异步并发 + 真实数据的基础上，扩大规模验证结论的统计显著性。50 用户的结果方差太大（Hit@5 每变 1 个用户就是 ±2%）。

6
与 AFL 实验结果对比

TriRec (三方博弈) vs AFL (双 Agent 反馈闭环) 在同数据集上的效果对比。两篇都是 Agent-based 推荐，但机制不同：TriRec 是单轮三方协作，AFL 是多轮双方反馈。
