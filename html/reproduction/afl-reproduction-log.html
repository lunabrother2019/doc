1. 原理概述

核心思想：双 Agent 反馈闭环

AFL 同时构建两个 LLM Agent：Rec Agent（推荐方）和 User Agent（用户方），通过多轮文本反馈交互，互相改进。

三步实验流程

步骤脚本作用输入输出
Step 1 evaluate_rec.py 推荐评估：Rec Agent 主导，每轮推荐→用户反馈→写入双方 memory→下轮改进 LastFM 用户历史 + SASRec 先验推荐 NDCG/Recall 指标，双方 memory 存档
Step 2a evaluate_user_step1.py 用户模拟训练：在 A/B 数据上积累交互 memory LastFM A/B 数据 + SASRec 模型 User Agent memory 存档
Step 2b evaluate_user_step2.py 用户模拟评估：加载 memory 预测用户行为 Step 2a 的 memory 用户预测准确度

1 只支持 GPT API api_request.py 只有 gpt_api() 新增 glm_api()，endpoint 改为智谱 open.bigmodel.cn

6 SASRec 模型内部 device 仍为 cuda torch.load(map_location) 只管 tensor 搬迁，不改模型的 self.device 属性 load 后加 model.device = self.device; model.to(self.device)
7 multiprocessing worker 找不到 __main__.SASRec 模型 pickle 序列化了 __main__.SASRec，worker 的 __main__ 没有这个类 在所有 evaluate_*.py 顶部加 from utils.model import SASRec

6. 为什么模型越强闭环效果越好

传统推荐 vs AFL 的区别

传统推荐（单向）:
  推荐模型 → 推荐歌曲 → 用户点击/跳过
  模型只知道"没点"，不知道为什么

AFL（双向对话）:
  Rec Agent:  "推荐 Metallica，因为你最近听了很多重金属"
  User Agent: "拒绝，我听重金属只是因为朋友分享的，其实我更喜欢流行摇滚"
  Rec Agent:  (记住这个反馈) "那推荐 Paramore，流行摇滚风格"
  User Agent: "接受"

关键区别：反馈不再是 0/1 信号，而是自然语言解释。Rec Agent 能从"为什么被拒绝"中学到更精准的用户偏好。

闭环依赖的三个 LLM 能力

能力弱模型 (flash)强模型 (plus)
理解反馈 只理解到"不喜欢" → 下轮换完全不同风格 → 跑偏 理解到"风格对但太吵" → 推荐同风格安静的 → 越来越准
生成有用反馈 "I don't like this song." ← 没有信息量 "I prefer melodic vocals rather than heavy screaming." ← Rec Agent 可据此调整
格式遵循 常给多个推荐（"Alternatively..."），解析失败重试引入噪声 严格遵循 Reason/Item/Decision 格式，解析稳定

结论

闭环机制本身是好的，但它依赖 LLM 同时扮演好"推荐者"和"用户"两个角色：

  • 模型太弱：两个角色都演不好，反馈质量低 → 多轮交互引入噪声 → 效果不升反降（flash: -1.64%）
  • 模型够强：反馈有信息量 → 多轮越来越准（plus: +3.27%，相对 +9.3%）
  • 论文用 GPT-4o-mini：报告 +11.52% 相对提升，与 plus 趋势一致
