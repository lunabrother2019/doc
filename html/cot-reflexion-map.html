Huang et al. 将 CoT 推理引入具身 Agent：机器人用自然语言"内心独白"做闭环规划。证明语言作为模块间统一接口的可行性。
2022.10
ReAct
Yao et al. 将 CoT 推理与环境交互统一：Thought→Action→Observation 循环。成为几乎所有 Agent 框架的基础范式。
2023.03
Reflexion + CAMEL
Reflexion: 在 ReAct 基础上加入自然语言反思，从失败中学习。CAMEL: 将多 Agent 角色扮演系统化研究。两者分别推进了"个体反思"和"集体协作"。

Park et al. 将记忆流 + 反思 + 规划统一为完整的 Agent 架构。25 个 Agent 在沙盒中涌现社会行为。是 CoT/ReAct/Reflexion 思想的集大成应用。

四层架构：从推理到自我改进

CoT 到 Reflexion 的演化可以归纳为四个递进层次：

层次 能力 代表论文 核心贡献 小镇对应
L1 推理 生成中间步骤 CoT, Plan-and-Solve 让 LLM 能"想清楚" 规划模块的逐步分解
L2 行动 推理+环境交互 ReAct, Inner Monologue 让 LLM 能"边想边做" 感知→规划→执行循环
L3 反思 从经验中学习 Reflexion 让 LLM 能"从失败中改进" Reflection 反思模块
L4 搜索 系统性探索+回溯 ToT, LATS 让 LLM 能"系统探索最优方案" 规划的多方案评估
关键洞察：每一层都是前一层的超集

L2(行动) = L1(推理) + 环境交互。L3(反思) = L2(行动) + 经验记忆。L4(搜索) = L3(反思) + 多路径探索。LATS 之所以是集大成者，正是因为它同时具备了所有四层能力。

4

CoT → Reflexion 核心路径解析

4.1 CoT 解决了什么问题？

LLM 在面对复杂推理任务时，直接输出答案的准确率很低。CoT 通过让模型"说出思考过程"来暴露中间推理步骤，将复杂问题分解为可管理的子步骤。这是一种推理时计算(inference-time compute)的思路——用更多 token 换取更好的结果。

4.2 ReAct 将推理接地(ground)

CoT 的问题：推理可能不忠实(unfaithful)，模型可能在推理链中幻觉。ReAct 的解决方案：让推理与环境交互交替——每次推理后执行行动，用真实观察来校正推理。这将 CoT 从"自说自话"变为"与世界对话"。

4.3 Reflexion 加入长期学习

ReAct 的问题：每次任务都从零开始，不能从过去经验中学习。Reflexion 的解决方案：任务失败后生成自然语言反思（"我上次忘了检查边界条件"），存入 episodic memory，下次检索复用。这将 Agent 从无状态执行器变为持续学习者。

核心演化公式

CoT（推理）+ 环境交互 = ReAct（行动）

ReAct（行动）+ 经验记忆 = Reflexion（反思）

Reflexion（反思）+ 树搜索 = LATS（系统搜索）

4.4 与斯坦福小镇的映射

斯坦福小镇的架构完美体现了这条演化路径：

  • Memory Stream = 经验存储（类似 Reflexion 的 episodic memory）
  • Reflection = 从记忆中提炼洞察（Reflexion 的反思机制）
  • Planning = 基于推理的行动规划（CoT + Plan-and-Solve）
  • Action = 与环境交互（ReAct 的行动循环）

小镇是在 2023 年 4 月发布的——恰好在 CoT(2022.01)、ReAct(2022.10)、Reflexion(2023.03) 之后，吸收了这些工作的精华。
