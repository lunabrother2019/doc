论文概述：让 LLM 既能思考又能行动

2022 年末，普林斯顿大学和 Google Brain 的 Shunyu Yao 等人提出了 ReAct（Reasoning + Acting），解决了一个关键问题：如何让 LLM 在推理的同时与外部环境交互。

核心洞见
人类在解决问题时，推理和行动是交替进行的 -- 我们思考要搜索什么（Thought），然后去搜索（Action），看到结果后（Observation）再思考下一步。ReAct 将这一自然模式形式化为 LLM 的提示范式：Thought → Action → Observation 循环，直到任务完成。

ReAct 的影响远超论文本身。它成为了几乎所有现代 Agent 框架（LangChain、AutoGen、CrewAI 等）的核心循环模式。可以说，ReAct 定义了"什么是 LLM Agent" -- 一个能推理并与环境交互的系统。

斯坦福小镇的 Agent 循环（感知 → 规划 → 行动 → 反思）与 ReAct 的 Thought-Action-Observation 循环有着深层的结构对应。两者都让 LLM 在思考和行动之间交替。区别在于小镇是"预先规划型"（proactive），ReAct 是"实时反应型"（reactive）。

核心机制：Thought-Action-Observation 循环

ReAct 的核心是一个简洁而强大的三步循环：

ReAct 循环 Thought(t) → Action(t) → Observation(t) → Thought(t+1) → Action(t+1) → ...

Thought（思维链推理）

推理与计划生成
LLM 在自然语言空间中进行推理，分析当前状态、制定下一步行动计划。Thought 不会被发送到环境，而是作为模型的"内心思考"。例如："我需要查找 X 的出生年份，然后再查找 Y 的出生年份，最后比较两者。"

Action（环境交互）

执行具体操作
基于 Thought 的推理结果，模型生成一个具体的、可执行的动作。动作类型取决于环境：在知识问答中是 Search[query] / Lookup[term]；在游戏中是 go to[location] / pick up[object]；在网页中是 click[element] / type[text]。

Observation（环境反馈）

接收执行结果
环境返回 Action 的执行结果。这是 ReAct 与纯 CoT 的根本区别 -- CoT 只在模型内部推理，而 ReAct 能获取真实的外部信息。Observation 为下一轮 Thought 提供新的事实基础，确保推理基于真实数据而非模型的"想象"。
关键创新：推理与行动的协同增强
ReAct 的核心创新不是"推理"或"行动"本身（CoT 已经实现了推理，传统 Agent 已经实现了行动），而是将两者在同一个 prompt 中交替进行。Thought 为 Action 提供计划和方向，Observation 为 Thought 提供事实基础，两者形成正反馈循环。

完整示例：HotpotQA 多跳问答

问题："Colorado Orogeny 山脉的东部区域延伸到了哪个地区？"

  • Thought 1: 我需要搜索 Colorado Orogeny，找到其东部区域延伸到的地区。
  • Action 1: Search[Colorado Orogeny]
  • Observation 1: The Colorado Orogeny was an episode of mountain building... The eastern sector extends into the High Plains...
  • Thought 2: 搜索结果提到东部区域延伸到了 High Plains。但我需要确认这是否是最终答案。
  • Action 2: Lookup[eastern sector]
  • Observation 2: The eastern sector extends into the High Plains of New Mexico and Colorado.
  • Thought 3: 东部区域延伸到了 High Plains。答案是 High Plains。
  • Action 3: Finish[High Plains]

注意每一步 Thought 如何消化前一步的 Observation，并为下一步 Action 提供指导。这种"闭环推理"是 ReAct 的精髓。

关键实验：知识推理 + 决策任务

Yao et al. 在三个具有代表性的基准上验证了 ReAct，涵盖知识密集型推理和交互式决策两大类别。

HotpotQA：多跳知识问答

任务：需要整合多个维基百科页面信息的问答

方法EM (Exact Match)F1特点
标准 Prompting 25.7% 32.6% 无推理，无搜索
CoT Prompting 29.4% 37.1% 有推理，但可能幻觉
ReAct 35.1% 40.8% 有推理 + 真实搜索
ReAct + CoT-SC 39.5% 46.7% 融合两者优势

ReAct 超越纯 CoT 的关键原因：通过实际搜索获取事实，避免了 CoT 的幻觉问题。CoT 在推理正确但事实错误时会"自信地给出错误答案"，而 ReAct 通过查证来纠正这一问题。

ALFWorld：交互式文本游戏

任务：在虚拟家庭环境中完成日常任务（如"在台灯下检查物品"）

方法成功率说明
BUTLER (模仿学习) 37% 从专家示范中学习策略
ReAct (1-shot) 71% 仅用1个示例，超越模仿学习 +34%
ReAct (3-shot + 反思) 78% 加入失败后自我反思机制

ALFWorld 的结果尤其令人印象深刻：仅用 1 个示例就超越了需要大量训练数据的模仿学习方法。这证明了 ReAct 范式的样本效率极高。

WebShop：网页购物任务

任务：在模拟电商网站上根据需求购买商品

ReAct 超越了强化学习（RL）基线约 10%，展示了在复杂网页交互场景下推理与行动结合的优势。模型需要理解商品描述、对比选项、做出购买决策 -- 这正是 Thought-Action-Observation 循环的天然应用场景。

三个基准的共同结论
在所有需要"从外部获取信息"或"与环境交互"的任务上，ReAct 都显著优于纯推理（CoT）方法。核心优势在于 Observation 提供了真实的外部信号，打破了 LLM 的"封闭推理"局限。

ReAct vs 纯 CoT vs 纯 Acting：三种范式对比

理解 ReAct 的最佳方式是将它与两个"退化版本"进行对比：

纯 CoT（Reasoning Only）
优势：强大的内部推理能力，能进行复杂的逻辑推演
劣势：封闭在模型内部，容易产生幻觉；无法获取最新信息；无法验证推理中的事实假设
类比：闭着眼睛思考的人
纯 Acting（Acting Only）
优势：能与环境交互，获取真实信息
劣势：缺乏高层规划，行动是"反射式"的；无法进行长期推理；容易陷入无效的行动循环
类比：不经思考就行动的人
ReAct（Reasoning + Acting）
优势：推理指导行动方向，观察校正推理偏差；减少幻觉，提高决策质量
劣势：更多 token 消耗，更高延迟；依赖良好的环境接口设计
类比：边想边做、边做边调整的人
CoT 的幻觉问题 vs ReAct 的解决方案
Yao et al. 发现，在 HotpotQA 上，纯 CoT 的错误中有 33% 是事实幻觉 -- 模型"编造"了看起来合理但实际不存在的事实。而 ReAct 通过 Search 动作查证事实，将幻觉率降至几乎为零。这是 ReAct 最具实际意义的贡献之一。

融合策略：ReAct + CoT-SC

Yao et al. 进一步提出了ReAct + CoT Self-Consistency的融合策略：

  1. 先用 ReAct 尝试解决问题
  2. 如果 ReAct 的搜索结果不充分，切换到 CoT 进行内部推理
  3. 综合两者的答案，用多数投票选出最终结果

这种融合策略在 HotpotQA 上达到了最佳性能（EM 39.5%），证明了推理和行动的互补性。

对 Agent 框架的深远影响

ReAct 的影响远远超出了论文本身。它定义了现代 LLM Agent 的基本架构模式，几乎所有主流 Agent 框架都以 ReAct 循环为核心。

框架 ReAct 循环实现 扩展特性
LangChain AgentExecutor 类直接实现 Thought-Action-Observation 循环 工具注册、记忆、链式组合
AutoGen 多 Agent 对话中的推理-行动模式 多 Agent 协作、代码执行
CrewAI Agent 的 Task 执行遵循 ReAct 模式 角色定义、任务委托

从学术论文到工业标准
ReAct 是少数直接从学术论文转化为工业标准的 AI 研究成果之一。当开发者说"我要构建一个 Agent"时，他们通常指的就是实现一个 ReAct 循环：让 LLM 推理要做什么、调用工具执行、获取结果、再推理下一步。这种模式已经如此普遍，以至于很多人使用它而不知道其学术源头。

ReAct 的演进方向

Reflexion (2023)
在 ReAct 基础上加入自我反思机制。当任务失败时，Agent 生成反思总结并在下一次尝试中利用。将 ReAct 的单次循环扩展为多次尝试的学习过程。
LATS (2023)
将蒙特卡洛树搜索与 ReAct 结合。在 Thought 阶段不是只生成一条推理路径，而是搜索多条可能的路径，选择最优的 Action。
Plan-and-Execute (2023)
将 ReAct 分为两阶段：先用 LLM 生成完整计划，再逐步执行。解决了 ReAct 在长链任务上容易"迷失方向"的问题。
Multi-Agent ReAct (2023+)
多个 Agent 各自运行 ReAct 循环，通过消息传递协作。MetaGPT、ChatDev 等系统的核心模式。

与斯坦福小镇的关联：两种 Agent 循环的对比

斯坦福小镇和 ReAct 都是 2022-2023 年间定义"LLM Agent"概念的关键工作，两者从不同角度切入了同一个问题。

结构对应

ReAct 斯坦福小镇 对应关系
Thought Planning + Reflection 内部推理过程
Action Action (行动执行) 与环境的交互
Observation Perception (感知) 从环境获取反馈

关键差异：Reactive vs Proactive

ReAct：实时反应型（Reactive）

ReAct Agent 在每一步都根据当前 Observation 决定下一步行动。它没有长期计划，每一步的推理都是"短视的" -- 只考虑如何推进当前任务的下一步。这种模式适合明确的、有终止条件的任务（回答一个问题、完成一次购物）。

斯坦福小镇：预先规划型（Proactive）

小镇 Agent 先生成整天的日程计划，然后按计划行动。当遇到意外（如其他 Agent 的对话邀请）时才做反应式调整。这种模式适合需要长期一致性的场景（模拟一个人的日常生活）。

互补而非竞争
ReAct 和斯坦福小镇的 Agent 循环不是竞争关系，而是互补关系。一个完整的 Agent 系统可能需要两者的结合：
  • 高层规划用小镇的 Proactive 模式（先规划日程/任务列表）
  • 任务执行用 ReAct 的 Reactive 模式（逐步推理并与环境交互完成每个子任务）
事实上，这正是 Plan-and-Execute 等后续工作所探索的方向。
小镇的规划 → 行动 → 感知循环本质上是 ReAct 的具象化。区别在于小镇是预先规划（proactive），ReAct 是实时反应（reactive）。两者互补：小镇的 Agent 在"按计划行动"时近似于 Acting-only，在"遇到意外重新规划"时近似于 ReAct。一个理想的 Agent 系统应该兼具两种模式 -- 有长远规划，也能在执行中根据环境反馈实时调整。ReAct 论文为这种"闭环执行"提供了形式化的理论基础。
