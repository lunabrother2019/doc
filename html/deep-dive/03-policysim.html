论文概览

PolicySim: An LLM-Based Agent Social Simulation Sandbox for Proactive Policy Optimization
LLM Agent 社交模拟 策略优化 上下文赌博机 SFT + DPO 回声室

作者：Renhong Huang, Ning Tang, Jiarong Xu, Yuxuan Cao 等

发表：ACM Web Conference 2026（迪拜），arXiv 2603.19649，2026 年 3 月

代码：https://github.com/renH2/PolicySim

核心思想 将社交平台策略评估从被动式 A/B 测试（先部署、再发现问题）转变为主动式模拟-优化（先模拟、再部署）。PolicySim 构建了一个完整的 LLM 智能体社交模拟沙盒，能够在部署前预演推荐、内容过滤和曝光控制等干预策略，并通过上下文赌博机（Contextual Bandit）迭代优化干预参数。
真实用户数据 → SFT + DPO 训练 → 智能体社交模拟 → 干预策略施加 → 赌博机优化 → 最优策略输出
2

问题背景

社交平台部署的干预措施——推荐算法、内容过滤、曝光控制——本意是提升用户体验，但往往会无意中放大回声室效应和群体极化。用户被困在同质化信息茧房中，极端观点得到强化，跨立场对话消失。

被动式 A/B 测试的三大失败

1  风险识别滞后

伤害只有在策略实际部署到真实用户之后才能被发现。政治极化、虚假信息扩散等系统性风险往往需要数周甚至数月才能显现，此时已经造成了不可逆的社会影响。

2  回滚成本高昂

一旦发现问题，策略回滚不仅意味着巨大的运营成本，还会造成用户信任的损失。频繁的策略变更让用户感到混乱，平台声誉受损。

3  缺乏优化闭环

现有模拟方法（如 OASIS、S3 等）侧重于观察和描述智能体行为，但缺乏利用反馈信号迭代优化策略的原则性机制。模拟完成后，策略改进仍然依赖人工经验。

关键洞察 PolicySim 的核心价值在于补齐了「模拟 → 优化」的最后一环。它不仅能回答「如果施加干预 X，社交网络会怎样？」，还能进一步回答「最优的干预 X 是什么？」——这是从描述性（descriptive）到处方性（prescriptive）的范式跃迁。
3

架构深度解析

PolicySim 的架构分为两大核心模块：用户智能体模块（User Agent Module）和自适应干预模块（Adaptive Intervention Module），通过模拟循环（Simulation Loop）将二者耦合。

3.1 用户智能体模块 (User Agent Module)

用户画像构建 (User Profile Construction)

每个智能体基于真实平台数据构建画像，包含 4 个核心属性，记为 φ(u_i)：

Likely Identity

用户的可能身份画像——年龄段、职业方向、政治倾向等，从历史行为数据中推断。

Interested Areas

用户关注的话题领域，基于历史发帖和互动内容提取。

Posting Style

用户的发帖风格——语言习惯、情感基调、内容长度偏好等。

Interaction Behavior

用户的互动行为模式——倾向于点赞还是评论、对争议话题的参与度等。

行为空间 (Action Space)

智能体每轮可执行多个动作（非互斥），行为空间包括：

  • tweet（发帖）、retweet（转发）、reply（回复）
  • like（点赞）、dislike（踩）、do nothing（无操作）
  • follow / unfollow（关注 / 取消关注）——这是 PolicySim 的关键创新，使得社交网络拓扑可以动态演化

动态网络 (Dynamic Network)

社交网络建模为时变有向图：

Gt = (V, Et)     序列 {G1, G2, ..., GT} 捕捉网络拓扑演化

由于智能体可以执行 follow/unfollow 操作，边集 Et 随时间步变化。这意味着回声室的形成和瓦解都可以在模拟中被自然捕捉。

立场追踪 (Stance Tracking)

智能体的立场取离散值 {-1, 0, 1}，由 LLM 基于行为内容分类。为避免剧烈跳变，采用指数移动平均（EMA）平滑：

stancet = α × stancet-1 + (1 - α) × raw_stancet     (α = 0.8)

双层记忆系统 (Dual-Layer Memory)

短期记忆 (Short-term)

通过 LLM 对近期交互进行摘要处理，保留关键信息的压缩表示。类似人类对最近对话的即时记忆。

长期记忆 (Long-term)

基于嵌入向量 + 时间戳存储。检索时使用余弦相似度，并施加指数衰减权重（λ = 1），使较新的记忆具有更高的检索优先级。

3.2 SFT 监督微调训练

训练数据集 DSFT

从目标平台采集真实数据，构建 (event, user_profile, observed_action + content) 三元组。每条样本将一个热点事件和用户画像映射到该用户的实际行为和发帖内容。

参数 值
基座模型Qwen2.5-3B-Instruct（32K 上下文窗口）
微调方法LoRA，rank = 64
学习率1e-6
批大小256
训练轮次10 epochs
硬件12 × NVIDIA A100-PCIE-40GB

3.3 DPO 偏好对齐训练

在 SFT 模型基础上进一步应用 DPO（Direct Preference Optimization） 对齐：

  • 偏好样本 y+：真实人类行为（ground truth）
  • 拒绝样本 y−：模型生成的候选行为，J = 3 个负样本，选择与真实响应相似度最低的生成结果
  • DPO 温度：β = 0.5
  • 学习率：5e-7
为什么 SFT + DPO？ 单独的 SFT 能让模型学会「像人一样发帖」，但可能在边界情况下产生不自然的行为。DPO 通过偏好对齐进一步约束模型，使其在行为分布层面更贴近真实用户。消融实验证实：SFT+DPO 的完整流水线在所有指标上优于单独使用任一方法。

3.4 自适应干预模块 (Adaptive Intervention Module)

推荐系统：三通道架构

关系通道 (Relational)

推荐用户已关注的人的帖子。维护社交信任链上的信息流。

个性化通道 (Personalized)

基于语义对齐推荐与用户兴趣匹配的内容。使用嵌入相似度排序。

热点通道 (Headlines)

推荐热门趋势内容。确保用户能接触到平台上广泛讨论的话题。

曝光控制 (Exposure Control)

exp(ui) ∈ [0, 1]  —  帖子通过内容过滤器的概率

曝光控制是一个连续值参数，决定特定帖子是否能被目标用户看到。值越低，过滤越严格。这可以用于限制虚假信息的传播。

上下文赌博机 (Contextual Bandit)

状态：St = (U, Gt, R) —— 用户集合 U、当前网络拓扑 Gt、推荐状态 R

臂 (Arms)：user-post 对（推荐决策）或 user-probability 对（曝光控制）

奖励函数（跨视角推荐）：

reward = (stance divergence) × (engagement) × (toxicity penalty)

其中毒性惩罚通过 Perspective API 计算，惩罚系数 μ = 4。这确保了系统在促进跨立场对话的同时不会导致毒性内容的增加。

消息传播机制 (Message Passing)

Xuser(k) = γ · Xuser(k-1) + (1 - γ) · D-1 · A · Xuser(k-1)

其中 A 为 Gt 的邻接矩阵，D 为度矩阵，k = 1 跳。该机制捕捉网络拓扑的演化对用户状态的影响——邻居的观点会通过图结构传播并影响个体。

优化：探索-利用网络

利用网络 gθ

context → reward 的直接映射。基于当前已知信息选择预期奖励最高的臂。

探索网络 ĝφ

估计每个臂的潜在增益。引导系统尝试那些不确定性高但可能具有更高回报的选择。

score(arm) = gθ(x) + ĝφ(∇)

3.5 模拟循环 (Simulation Loop)

1. 初始化智能体画像 + 初始网络拓扑
↓
2. 每轮：智能体执行行为 → 3. 施加干预策略 → 4. 更新立场 + 累积记忆 + 演化网络
↓
5. 计算生态系统奖励信号 → 6. 赌博机更新干预参数
↓
7. 迭代 T 轮 → 输出最优策略
闭环优化 与纯观测性模拟不同，PolicySim 的模拟循环形成了一个完整的优化闭环：模拟产生数据 → 数据计算奖励 → 奖励更新策略 → 策略改变模拟 → 再次产生数据。这正是它区别于 Smallville、OASIS 等系统的核心所在。

实验结果

数据平台

Twitter (TwiBot-20)

229K 用户、3350 万条推文、45.6 万条关注关系。大规模真实社交网络数据集，涵盖多种话题和用户类型。

Weibo（微博）

用于跨平台迁移验证，测试模型在不同文化和语言环境下的泛化能力。

4.1 微观行为精度 (Micro-level Accuracy)

在 TwiBot-20 数据集上，PolicySim 与基线方法的逐用户行为还原精度对比：

指标 Random GLM4-light Llama-3-8B PolicySim
BERTScore F1 28.55 46.01 46.32 58.05
BERTSim 74.42 81.95 85.22 88.06
行为对齐率 (Behavior Alignment) 36.11% 48.33% 52.36% 65.56%
分析 PolicySim 在 BERTScore F1 上超出最强基线（Llama-3-8B）+11.73，行为对齐率提升 +13.20%。自一致性（Self-consistency）相比基线提升了 10.15%。SFT+DPO 的双阶段训练显著提升了模型对真实用户行为的拟合度。

4.2 回声室与极化效应 (Echo Chamber / Polarization)

这是 PolicySim 最核心的实验——验证干预策略能否打破回声室并降低极化：

方法 立场标准差
(越高越多样)		 毒性
(越低越好)		 跨立场互动
(越高越好)		 虚假信息
(越低越好)
无干预 0.014 0.0556 4% 40%
ε-greedy 0.184 0.0426 14% 26%
UCB 0.026 0.0628 50% 30%
PolicySim 0.376 0.0386 56% 24%

关键发现

回声室被有效打破 无干预时，跨立场互动仅 4%（强回声室效应）。PolicySim 将其提升至 56%，增长了 14 倍。
多样性不需要毒性 PolicySim 的毒性水平为 0.0386，是所有方法中最低的。证明促进观点多样性与控制毒性并不矛盾。
UCB 的代价 UCB 也实现了 50% 的跨立场互动，但其毒性水平为 0.0628——所有方法中最高。PolicySim 在更好的多样性下实现了更低的毒性。
虚假信息抑制 虚假信息占比从无干预的 40% 降至 PolicySim 的 24%。曝光控制机制有效限制了虚假内容的传播。

4.3 规模性能

运行时间与智能体数量呈线性关系（r = 0.9904），测试规模达 1,000 个智能体。这意味着系统在工程上可扩展，尽管绝对规模仍有限。

4.4 消融实验 (Ablation)

变体 说明 效果
PolicySim-φ 移除用户画像 所有指标大幅下降 —— 画像是行为拟真的关键
PolicySim-DPO 仅 DPO，无 SFT 弱于 PolicySim-SFT —— 无监督基础的偏好对齐效果有限
PolicySim-SFT 仅 SFT，无 DPO 表现良好但不及完整流水线 —— DPO 提供了额外的行为校准
PolicySim (完整) SFT + DPO + 画像 所有指标最优

4.5 策略场景实验 (Policy Scenarios)

场景一：反堕胎立法

基于 2022 年 6 月（Roe v. Wade 被推翻后）的 10 条触发性新闻。模拟了跨视角内容推荐如何影响围绕堕胎议题的观点分布和互动模式。PolicySim 的干预策略成功促进了对立阵营之间的对话，而不是将用户推向更极端的位置。

场景二：虚假信息传播

初始化 20% 的用户携带宣传性虚假推文。通过曝光控制机制限制虚假信息的传播范围。实验验证了适当的曝光控制参数能够在不过度审查的前提下有效抑制虚假信息的扩散。

局限性

规模受限

测试规模上限约 1,000 个智能体，而 OASIS 等系统已达到 100 万。对于需要模拟大规模网络效应的场景，当前规模可能不足。

算力需求

训练需要 12 块 A100 GPU，即使选择了相对较小的 3B 模型，硬件门槛仍然很高，限制了研究的可复现性。

行为一致性假设

模型假设用户的历史行为模式在面对全新策略时仍然成立。但对于前所未有的干预措施，用户可能产生完全出乎预料的行为反应。

干预类型有限

目前仅支持推荐和曝光控制两种干预方式。不支持 UI 提示（nudges）、透明度工具、限流（rate limiting）等现实平台常用的治理手段。

奖励设计的主观性

跨视角推荐的奖励函数（立场分歧 × 参与度 × 毒性惩罚）的设计和参数选择具有主观性。不同的奖励设计可能导致截然不同的最优策略。

离散立场的粗糙性

立场取 {-1, 0, 1} 三个离散值过于粗糙。现实中的观点是连续且多维的，三值编码无法捕捉观点的细微差异和演化。

Perspective API 偏差

毒性检测依赖 Perspective API，而该 API 已知对某些方言、语言和文化背景存在系统性偏差，可能影响奖励信号的公平性。

缺乏真实部署验证

所有实验均在模拟环境中完成。模拟中的最优策略是否在真实平台上同样有效，尚未得到验证。模拟与现实之间的 sim-to-real gap 仍是开放问题。

与斯坦福小镇的关联

PolicySim 与 Smallville（斯坦福小镇）代表了 LLM 智能体模拟的两种不同范式。理解它们之间的差异和演进关系，有助于把握该领域的发展脉络。

维度 Smallville（斯坦福小镇） PolicySim
目的 观察涌现行为 工程化干预策略并优化
环境 物理小镇（2D 地图） 社交媒体平台
智能体基础 手写传记（biography） SFT + DPO 对齐真实用户数据
社交网络 隐式（基于空间邻近性） 显式有向图，支持动态演化
平台角色 不存在 主动中介者（推荐 + 曝光控制）
优化机制 无（纯观测） 上下文赌博机迭代优化
规模 25 个智能体 最多 1,000 个智能体
记忆架构 反思-检索-规划（Reflect-Retrieve-Plan） 双层记忆（短期摘要 + 长期嵌入 + 时间衰减）
概念跃迁 Smallville 回答的问题是：「当智能体自由互动时会发生什么？」
PolicySim 回答的问题是：「当平台介入干预时会发生什么？我们如何优化这些干预？」

这代表了从描述性范式（Descriptive）到处方性范式（Prescriptive）的根本性转变。PolicySim 不满足于观察和记录——它的目标是在部署前确定最优干预策略。
从 Smallville 到 PolicySim 的演进路径
Smallville (2023)
涌现行为观察 → S3 / OASIS
社交平台模拟 → PolicySim (2026)
模拟 + 优化闭环

Smallville 证明了 LLM 智能体可以产生可信的社会行为；S3、OASIS 等工作将模拟环境从物理小镇拓展到社交平台；PolicySim 在此基础上补齐了优化闭环，完成了从「能模拟」到「能优化」的最后一步。
