AgentBench：首个系统化 Agent 评测基准

清华 THUDM（Xiao Liu, Hao Yu 等 22 人）+ Ohio State。ICLR 2024。

关键发现

  • GPT-4 大幅领先所有开源模型（≤70B）
  • 失败主因：long-term reasoning 薄弱 + instruction following 差
  • Code training 对 agent 任务影响具有两面性（非单纯正面）

FireAct：多方法 Trajectory 微调

Princeton（Baian Chen, Shunyu Yao = ReAct 作者）+ Monash + Cambridge。2023.10。

核心发现
用 GPT-4 生成的 agent trajectory 数据微调 Llama2-7B，仅 500 条数据 即获 HotpotQA 77% 性能提升。多样化数据源（混合 ReAct + CoT + Reflexion trajectory）比单一来源效果更好。

关键设计：从 ReAct / CoT / Reflexion 等多种 prompting method 分别生成 trajectory，混合训练。这证明 Agent 的推理模式可以通过 SFT "烤进"小模型。

代码：github.com/anchen1011/FireAct

4

AgentTuning：Hybrid SFT 保通用能力

清华 THUDM（Aohan Zeng 等，与 AgentBench 同组）。2023.10。

AgentInstruct 数据集

从 AgentBench 的 6 个环境筛选高质量交互轨迹，构成 1866 条 AgentInstruct。关键创新：与通用 ShareGPT 数据按比例混合做 SFT → 产出 AgentLM（7B / 13B / 70B）。

Hybrid 策略是核心
纯 agent 数据训练会损害通用能力（模型变成只会做 agent 任务的专才）。混合通用数据后两者兼得：AgentLM-70B 在 held-out agent tasks 上媲美 GPT-3.5-turbo，同时通用 benchmark 不下降。

代码：github.com/THUDM/AgentTuning（开源 AgentInstruct + AgentLM 权重）

对 Generative Agents 的意义：小镇的 25 NPC 全部依赖 GPT-3.5/4 级别模型——成本高、延迟大、无法离线。这三篇证明了小镇式 Agent 的 planning/memory/tool-use 能力可以通过轻量 SFT 注入开源模型（7B 级），为低成本规模化部署 generative agent 系统铺路。具体路径：用 AgentBench 环境生成训练数据 → FireAct/AgentTuning 方法微调 → 得到可本地部署的"小镇级"Agent LLM。
📌 一句话记住
AgentBench 定义了"好 Agent 长什么样"（8 环境评测），FireAct 和 AgentTuning 证明了"少量高质量 trajectory SFT 就能训出好 Agent"（500 条数据 +77%），三者形成 evaluate→train 闭环。对小镇架构的实际意义：GPT-4 级 Agent 能力可以蒸馏到 7B 模型。
