1

一句话定位：让 LLM 在"不一致的物理世界"里说出该说的"不"

过去的 LLM 幻觉研究集中在 QA / 文本生成——一句话是否符合事实。而一旦把 LLM 放进机器人成为 goal interpreter，"幻觉"就变成：LLM 无法把用户指令 grounding 到它所观察的物理场景上。本文把这种现象精确命名为 scene–task inconsistency hallucination，并首次用系统性实验把它测出来。

论文的核心主张（原文精炼）

"Hallucinations in embodied agents stem from a failure to ground user-provided task instructions in the observed physical environment ... this misalignment can lead to consequences far more seriously than a simple textual error."
—— 让一个无洗碗机的家里的机器人"把刀放进洗碗机"，它会捏造一个洗碗机并把刀丢进空柜子或按空墙上的按钮。

2

具身幻觉特殊在哪：感知-行动回路中的错觉

纯 LLM 的幻觉是"说了一句不对的话"，比较可以用事实核查。具身 Agent 的幻觉是"基于不存在的物理对象产生了可执行计划"，它的特殊之处在于 错觉会沿着感知→推理→执行这条回路跑一遍，最终变成物理动作。

2.2 具身场景下"幻觉"的形式化定义

论文 Equation 3（改写）

设场景对象集合 O、允许状态集合 S；模型输出 y 中提到的对象/状态记为 F_obj(y) / F_state(y)。幻觉发生的充要条件：
∃ o_k ∈ F_obj(y), o_k ∉ O 或 ∃ s_k ∈ F_state(y), s_k ∉ S
—— 即输出 LTL 里引用了"不在场景里的东西"。此定义可被自动化精确检测，不需要人类打标签。

2.3 三类具身特有失败：感知-规划断链

① 物体幻觉（Object Hallucination）

LTL 引用场景不存在的物体（如"打开洗衣机"但场景只有 table/cupboard/plate）。用 CHAIR-O（CO） / POPE-O（PO） 测量。

② 状态幻觉（State Hallucination）

预测了允许集之外的状态（洗衣机允许 {CLOSED, OPEN, PLUGGED_IN} 但输出 state: ON）。通常较少但会被物体幻觉串联触发。用 CHAIR-S（CS） 测量。

③ 计划失败但不是幻觉（Silent Planning Failure）

最隐蔽的新种类：模型不幻觉，但"挪用不相关对象硬凑任务"——任务打开洗衣机、场景只有淋浴，模型就开淋浴。不违反 grounding 定义，但行为仍错且危险（Table 6）。

关键洞察：无幻觉 ≠ 正确

"The absence of hallucination does not guarantee correct planning." 检测幻觉只是第一层防御，第二层还要检测"不该规划时的规划"。

3

实验设计：HEAL 探针集 + 12 模型 × 2 仿真器

3.1 基础 pipeline 与 HEAL 的扰动方式

论文基于 Embodied Agent Interface（Li et al. 2024b，NeurIPS）这一既有 benchmark。基础 pipeline 是：感知模块 P 把视觉 x_i 转成结构化场景 x_s（由 (物体, 初始状态, 可能状态) 三元组构成）；LLM 作为 goal interpreter 读取 (x_td, x_s) 输出 LTL 目标（node goals + edge goals）。

HEAL 做的事是：只改动 x_td 或 x_s，构造 4 种不一致。

变体 1 · 改任务

DistInj（干扰物注入）

task 里塞一个场景中没有的对象（如"别撞到打印机"但场景无打印机）。幻觉 = 模型把 printer 写进 LTL。

变体 2 · 改场景

TaskObjRem（任务对象移除）

从场景里删除任务需要的关键物体（如删掉 washing_machine）。幻觉 = 模型仍引用被删对象。

变体 3 · 改场景

SynonymSub（同义词替换）

把 washing_machine 改成 washer、soap 改成 detergent。幻觉 = 输出仍用 washing_machine 而非新名。

变体 4 · 改场景

SceneTaskCon（场景-任务矛盾）

把场景换成完全无关的（task 要洗衣服，场景只有 table/plate）。正确行为应是拒绝规划。

3.2 评测指标

CHAIR（CO / CS）—— 相对占比

幻觉对象/状态 占 输出中所有提及的对象/状态 的比例。反映"说的话里有多少是编的"。公式：C_t = |hallucinated_t| / |all_t mentioned|。

POPE（PO）—— 二分类准确率

预先构造"这个物体是否出现在输出中？"的 yes/no 问题集，测模型对人工注入的不存在物体是否会说 "yes"。不受输出长度偏置影响。

Refusal/Empty Rate（补充）

在 TaskObjRem 和 SceneTaskCon 下，正确行为应是拒绝/返回空计划。论文 Table 8 专门测这个率——大部分模型接近 0%，即"几乎从不拒绝"。<待实证>：具体数值分布需查 Table 8 完整版。

3.3 被测模型与仿真器

12 模型覆盖：开源小模型（LLaMA-3-8B / Gemma-2-9B / Qwen-14B / DS-R1-Distill 系列）、中大模型（LLaMA-4-Scout-17B / LLaMA-3.3-70B / Mistral-Large）、闭源强模型（Claude 3.5 Sonnet / GPT-4o / Gemini 2.0 & 2.5 Flash）；VLM 消融用 Qwen-VL-7B、LLaMA-11B-Vision、Gemma-3-12b-it。仿真器：VirtualHome（抽象长程）+ BEHAVIOR-1K（低层 pick-and-place）。每设置 3 独立运行取均值。

3.4 缓解实验：两种 self-correction

  • KAF（Knowledge-Augmented Feedback）：给模型一般性提示，让它再改一遍。
  • SCW（Self-Correcting Woodpecker）：给出具体哪些对象是幻觉的反馈，让模型针对性修正。

结论剧透：SCW > KAF，但对 SceneTaskCon 几乎无效——即使告诉模型"washing_machine 是幻觉的"，它还是会再生成新的幻觉而不是拒绝任务。

关键发现：四个量化结论 + 一个工程警示

4.1 发现一：SceneTaskCon 是最强幻觉触发器

VirtualHome 上，SceneTaskCon 的 PO 指标最高可达 70.68%（Qwen-14B-Instruct）。即使是 Claude 3.5 Sonnet 这种强模型也达到 40.07%。直觉解释：模型把"完成任务"的优先级放在"尊重场景"之上，即使场景里毫无相关物体，也要强行凑出一个计划。

4.2 发现二：模型规模 ↑ → 幻觉 ↓，但 "拒绝能力"并不随之线性提升

总体上大模型（70B、闭源 Claude/Gemini）的 CHAIR 指标明显低于小模型（8B/9B）。但是 —— 关键反例：

  • Gemini 2.0 Flash 是唯一会显式拒绝的模型：当场景缺少关键物体时，它会说 "I cannot fulfill this request. There's not enough information about light." 并返回空 LTL（Table 5）。
  • Claude 3.5 Sonnet 和 GPT-4o 不幻觉但挪用物体：任务要打开洗衣机、场景只有淋浴，它们"贴心地"去打开淋浴（Table 6）。这是 §2.3 里的"第三类失败"。
模型的两个性格

结合 Table 5/6 可以把模型粗略分成两种风格：Gemini 派 —— 保守，会说"不"；Claude/GPT-4o 派 —— 热心，会挪用"。前者对不可行任务更安全，后者对歧义任务更"好用"。工程部署时这两种风格对应完全不同的 prompt / policy 策略。

4.3 发现三：SynonymSub 最容易，DistInj 中等——一个"命名一致性"悖论

SynonymSub 幻觉率最低（均值约 20%），说明模型理解同义关系——它知道 washer 就是 washing_machine；但它在输出里时而用 washer、时而偷偷用 washing_machine，失去命名一致性。论文 Table 4 给出例子：输出同时出现 bucket.n.01_1 和 pail.n.01_1。

根因猜测（论文 §5.1）

对话训练偏好"用词多样化"以显得自然；但具身 grounding 要求严格的词汇对齐——两者直接冲突。这意味着 instruction-tuning 阶段混入的"语言风格偏好"会反向伤害具身表现。

4.4 发现四：VLM 仅给图像反而更差，image+text 最好

Table 2（DistInj，VirtualHome）PO：Qwen-VL-7B 图/文/图+文 = 31.84 / 30.32 / 24.37；LLaMA-11B-Vision = 46.90 / 41.49 / 36.44；Gemma-3-12B = 36.67 / 32.99 / 24.14。两个信号：① 只给图像会让 VLM 幻觉更多（视觉编码器弱、"vision is blind" 效应）；② image+text 跨模态验证最稳，视觉应作核验而非唯一来源。

4.5 发现五（工程警示）：Post-hoc 自修正对 SceneTaskCon 近乎无效

Table 3：Qwen-14B-Instruct 在 SceneTaskCon 下，KAF 反馈后 PO 仍 55.37%；SCW 反馈（明确告诉它哪些是幻觉）后 PO 仍 42.35%。即使被显式告知"洗衣机不存在"，模型改一轮后还是会"发明"一个等价对象继续规划——一种顽固的"要完成任务"执念。

工程启示：幻觉不是"再想一遍就好"

这条经验与 #10 Reflexion、#28 Self-Correct Limits 的结论一致：self-correction 擅长修正"计算错误"，但不擅长修正"任务可行性误判"。真正要解决 SceneTaskCon 幻觉，需要前置的 solvability check（"这个任务在这个场景可行吗？"）而不是事后修正。

用 #40 找口袋、#29 GEA 拿底座、#48 HEAL 的探针集与 CHAIR/POPE 量化、#41 的三路径做干预——目前具身幻觉研究最短的"读论文→上手实验"路径。

5.3 映射到斯坦福小镇

小镇居民的 action 调用（walk_to, use_object 等）本质上就是具身任务。HEAL 发现的 4 种失败模式全部会发生：
  • DistInj：用户 context 里提到家里有一个其实不存在的物件 → 居民的计划引用它
  • TaskObjRem：地图里某 object 被随机事件移除但没同步到 memory → 居民仍想去用
  • SynonymSub：居民之间对话把"咖啡机"叫成"coffee maker" → 规划器输出不一致命名
  • SceneTaskCon：玩家临时换地图，但没人告诉居民 → 居民在错误场景里硬凑计划
小镇论文完全没有考虑这些失败模式，这对"用 Generative Agents 做机器人模拟"的后续工作是一个重要警示：原论文的成功部分建立在"静态完美场景"假设上，一旦把它推向真实/动态环境，本论文报告的 40–70% 幻觉率是绕不过的。

FAQ（两问）

Q1. 既然 #40 已经把 Agent 幻觉分成五阶段了，本论文（#48）还值得单独读吗？

值得，而且必读。三个理由：

  • 从概念到数字：#40 告诉你"Perception 幻觉存在"，#48 告诉你"在 VirtualHome 上 Qwen-14B 的 PO 是 70.68%、Gemini 2.0 Flash 是 20.08%"——没有这些具体数字，所有缓解方法都无法衡量是否有效。
  • 独有新现象：本论文揭示了#40 没有覆盖的第三类失败——不幻觉但挪用物体（Claude/GPT-4o 去打开淋浴代替洗衣机）。这是 Agent 特有但综述层面没命名的新模式。
  • 可复现的探针集：HEAL 数据集开源在 Hugging Face（Trishna13/HEAL），基于现有 Embodied Agent Interface benchmark 扩展。任何研究者都可以直接用这 2574 样本测自己的新 Agent——这是综述提供不了的工程抓手。

简言之：#40 / #41 是地图，#48 是第一个带坐标的勘探报告。

Q2. 要把本论文的结论落地到一个真实 robot agent（或 Smallville 改造），优先抓哪三件事？

按论文证据强度排序的三件事：

  1. 前置 Solvability Check，而不是事后 self-correct。论文 Table 3 明确证明：即使给出"washing_machine 是幻觉的"具体反馈，SCW 修正后 PO 仍在 25–42%。根因是模型有"必须完成任务"的执念。解法：在 LLM goal interpreter 之前加一个独立的二分类器——输入 (x_td, x_s) 输出"本任务在本场景是否可行"，不可行则直接返回空计划。这比事后修正 cost-efficient 得多。
  2. 跨模态验证而非单模态升级。Table 2 显示图+文联合输入比任一单模态幻觉更少。工程启示：不要指望换个视觉更强的 VLM 就解决问题，让 VLM 读结构化 x_s + 原始图像两路比较，把视觉当核验器而非主信息源。对应 #41 的 "cross-checking" 范式。
  3. 命名一致性约束。SynonymSub 幻觉（Table 1 显示 ~20% 的模型会丢失命名一致性）可以通过一个非常廉价的 post-processing 规则消除：扫描输出 LTL，把所有对象名替换为场景中 canonical 的名字。这件事不需要重训模型，一条正则 pass 就能修，但却能把 SynonymSub 的错误直接清零。适合作为任何具身 Agent 的默认后处理层。

不建议优先做的：fine-tune 一个新底座模型（成本高、效果不确定）、通用 self-correction 框架（已被论文证伪）。先做"检测+拒绝"，再想"升级生成"。<待实证>：Solvability Check 的准确率门槛需做消融实验判定。
