InteRecAgent：LLM-as-Brain + RecModel-as-Tool

微软亚洲研究院（Xu Huang, Jianxun Lian, Xing Xie 等）。核心洞察：已有的 ID-based 推荐模型（MF/DNN）很强，但不会说话；LLM 很会说话，但不懂 item ID 体系。解法：让 LLM 当"经理"，传统模型当"工具"。

1
Task Planning — 用户说"推荐像《盗梦空间》一样的电影"→ LLM 规划调用链：先 candidate retrieval → 再 ranking → 最后 filter
2
Tool Execution — 调用封装好的传统 RecModel API，获得结果
3
Reflection — 检查结果质量（数量够不够？多样性够不够？），不满意则重新规划

额外贡献：将 InteRecAgent 的能力蒸馏到 RecLlama（LLaMA-2 微调版），降低部署成本。

3

RecMind：Self-Inspiring Planning

核心创新是 Self-Inspiring 算法：每个中间步骤，LLM 回顾所有已探索状态再决定下一步——等于在 planning 中引入了 Tree-of-Thought 的全局回溯。

Self-Inspiring vs CoT vs ToT
  • CoT：线性推理，不回头
  • ToT：树状搜索，可回溯到父节点
  • Self-Inspiring：每步都看所有历史状态，不局限于树结构的父子关系

在 zero-shot 设定下达到与全量训练模型 P5 可比的性能——这证明 LLM 的 planning 能力可以补偿缺乏训练数据的劣势。

4

MACRec：MetaGPT 思想入推荐

清华大学（Wang, Ma, Zhang 等）。多 Agent 分工与 MetaGPT 的 SOP 流水线思想高度一致：

M
Manager — 任务调度与流程控制（= MetaGPT 的 PM）
A
Analyst — 分析用户画像/物品属性（= memory retrieval）
R
Reflector — 对推荐结果反思修正（= Reflexion 机制）
S
Searcher — 信息检索工具调用
I
Interpreter — 解析任务意图（= planning）

支持 4 类任务：rating prediction / sequential rec / conversational rec / explanation generation，通过不同 working flow 组合 Agent。

这三篇不是在"模拟用户"（那是 RecAgent/Agent4Rec 做的事），而是把推荐系统本身变成一个 Agent。小镇的 Agent 是 NPC；这里的 Agent 是推荐引擎。Memory 从"记住经历"变成"记住用户偏好"；Reflection 从"合成自我认知"变成"检查推荐质量"；Planning 从"安排一天日程"变成"规划推荐策略"。形式不同，认知架构同源。

对 Challenge 问题的意义

对验证鸿沟的贡献

这三篇本身不直接解决"仿真验证"问题——它们是被验证的对象而非验证工具。但它们提供了一个关键前提：当推荐系统本身是 Agent 时，"Agent 模拟用户 × Agent 推荐系统"形成了全 Agent 闭环——AFL (DD59) 正是在此基础上构建的双 Agent 共演化验证框架。
