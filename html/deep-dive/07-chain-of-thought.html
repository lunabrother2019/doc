论文概述：让 LLM 学会"想清楚再说"

2022 年初，Google Brain 的 Jason Wei 等人提出了一个看似简单却影响深远的想法：在 few-shot 示例中加入中间推理步骤，就能显著提升大语言模型的推理能力。这就是 Chain-of-Thought (CoT) Prompting。

核心思想
传统 few-shot prompting 只给出"问题 → 答案"的示例。CoT prompting 在中间加入推理链："问题 → 推理步骤1 → 推理步骤2 → ... → 答案"。这种看似微小的改变，让 GPT-3 (540B) 在 GSM8K 数学推理基准上从 18% 飙升到 74%。

CoT 的革命性在于：它不需要修改模型权重、不需要额外训练，仅通过改变提示格式就释放了 LLM 的潜在推理能力。这表明大模型在预训练过程中已经隐式地学到了推理能力，CoT 只是提供了一个"表达通道"让这些能力显现出来。

CoT 是 Generative Agents 中所有高级认知能力的技术基础。没有 CoT，Agent 就无法进行多步推理 -- 无论是规划日程、反思记忆还是生成对话。斯坦福小镇论文虽未显式引用 CoT，但其 Agent 的每一个"想清楚再做"的行为本质上都依赖于 LLM 的 CoT 能力。

核心机制：三种 CoT 变体

CoT prompting 发展出三种主要变体，适用于不同场景和需求：

变体一：Few-shot CoT（原始版本）

在示例中嵌入推理链

最初由 Wei et al. 提出的版本。在 few-shot 示例中，不仅给出问答对，还展示完整的推理过程：

  • 标准 few-shot："Roger 有5个网球，又买了2罐，每罐3个。问共有几个？答案：11"
  • CoT few-shot："Roger 有5个网球，又买了2罐，每罐3个。他买了 2 x 3 = 6 个网球。所以他现在有 5 + 6 = 11 个。答案：11"

推理链的加入让模型"学会"在回答前先展开推理。关键在于：推理链不需要特别精确或格式化，只要展示出逐步思考的模式即可。

变体二：Zero-shot CoT（"Let's think step by step"）

一句魔法指令

Kojima et al. (2022) 发现，仅在问题后追加"Let's think step by step"这一简单指令，就能在零样本设置下激发 LLM 的 CoT 能力。无需提供任何推理示例。

这一发现的意义在于：CoT 能力不是从示例中"学来"的，而是模型内在具备的 -- 只需要一个触发信号。Zero-shot CoT 在实际应用中极为方便，因为不需要为每个任务精心设计推理示例。

变体三：Auto-CoT（自动化推理链）

自动生成推理示例

Zhang et al. (2022) 提出 Auto-CoT，通过聚类和自动生成来构建 CoT 示例，避免了人工编写推理链的成本：

  1. 将测试问题按相似度聚类
  2. 从每个簇中选取代表性问题
  3. 用 Zero-shot CoT 自动为这些问题生成推理链
  4. 将生成的"问题+推理链"作为 few-shot 示例

Auto-CoT 的准确率接近人工 CoT，但完全自动化，适合大规模部署。

三种变体的权衡
  • Few-shot CoT：质量最高，但需要人工设计示例，不同任务需要不同示例
  • Zero-shot CoT：最简便，一句话即可，但在复杂任务上质量稍逊
  • Auto-CoT：平衡自动化与质量，适合工业级应用
CoT Prompting 的统一范式 Input → [Trigger: examples / instruction] → Step-by-step Reasoning → Final Answer

关键实验：三大推理类别

Wei et al. 在三大类推理任务上全面验证了 CoT 的有效性，涵盖算术推理、常识推理和符号推理。

算术推理（Arithmetic Reasoning）

基准 标准 Prompting CoT Prompting 提升
GSM8K（小学数学题） 18% 74% +56pp
SVAMP（数学文字题） 63% 80% +17pp
MAWPS（多步算术） 79% 93% +14pp
AQuA（代数文字题） 33% 52% +19pp

算术推理是 CoT 收益最大的领域。GSM8K 的 56 个百分点提升尤其惊人 -- 这些都是需要多步计算的小学数学题，标准 prompting 下模型几乎无法处理，而 CoT 使其能力接近人类水平。

常识推理（Commonsense Reasoning）

基准 标准 Prompting CoT Prompting 提升
CommonsenseQA 73% 80% +7pp
StrategyQA 65% 73% +8pp

常识推理的提升相对温和，因为这类问题更依赖世界知识而非多步计算。但 CoT 仍能通过让模型"说出"推理过程来减少错误。

符号推理（Symbolic Reasoning）

Last Letter Concatenation（末字母拼接）

任务：给定一组名字，拼接每个名字的最后一个字母。例如 "Amy Brown" → "yn"

CoT 在域内测试（2个词）上接近 100%，且能泛化到域外（4个词），而标准 prompting 在域外完全失败。

Coin Flip（硬币翻转）

任务：追踪一系列翻转/不翻转操作后硬币的正反面状态。

CoT 让模型能逐步追踪状态变化，而非试图"直觉猜测"最终结果。

实验的核心发现
CoT 在需要多步推理的任务上效果最为显著。任务越复杂（步骤越多），CoT 相对于标准 prompting 的优势越大。这是因为标准 prompting 要求模型在单次生成中"跳跃式"得出答案，而 CoT 允许模型逐步展开推理，每一步都降低了出错概率。

为什么有效：CoT 的三个解释

解释一：问题分解

CoT 将一个复杂问题分解为多个简单的子步骤。每个子步骤对 LLM 来说都是"容易"的，模型只需要在每一步做出局部正确的推理，而非一步到位地解决整个问题。

类比：人类解决复杂数学题时也不会"直觉"给出答案，而是列出演算步骤。CoT 本质上是让 LLM 模仿这种行为。

解释二：暴露中间过程

推理链的每一步都可以被检查和验证，这使得：

  • 可调试性：当答案错误时，可以精确定位推理链中出错的步骤
  • 可验证性：人类可以审查推理过程，判断答案是否可信
  • 可改进性：通过修正错误步骤的示例，可以针对性地提升特定推理能力

解释三：模型规模效应（Emergent Ability）

关键发现：仅在大模型上有效
CoT 仅在参数量超过约 100B 的模型上显现显著效果。在小模型（如 1B-10B）上，CoT 不仅没有帮助，有时反而会降低性能。这表明 CoT 能力是一种涌现特性（emergent ability） -- 需要足够的模型容量才能支撑多步推理。
CoT 效果与模型规模的关系 模型 < 10B: CoT ≈ 标准 prompting（甚至更差）  |  模型 > 100B: CoT >> 标准 prompting

这一发现具有深远的理论意义：它暗示存在某种"推理能力阈值"，只有当模型参数量超过这一阈值时，才具备支撑 CoT 推理的内在能力。这与近年来关于 LLM 涌现能力的研究形成了重要呼应。

局限性：CoT 并非万能

局限一：小模型无效

如前所述，CoT 在小模型上不仅无效，甚至可能有害。小模型倾向于生成不连贯或错误的推理链，导致最终答案偏离正确答案。这限制了 CoT 在资源受限场景下的适用性。

局限二：推理链的忠实性问题（Faithfulness）

模型生成的推理链可能并不忠实地反映其内部的实际推理过程。研究表明：

  • 模型可能先"决定"答案，再生成看似合理的推理链来"合理化"该答案
  • 修改推理链中的关键步骤，有时并不改变最终答案 -- 说明模型可能绕过了推理链
  • 推理链的"可解释性"可能只是表面上的，并非模型真正的决策依据

局限三：推理成本增加

CoT 要求模型生成更长的输出（推理链 + 答案），这意味着：

  • Token 消耗增加：推理链通常比直接答案长 5-10 倍
  • 延迟增加：更多 token = 更长的生成时间
  • 成本增加：在按 token 计费的 API 中，CoT 的费用显著更高

局限四：错误传播

推理链中早期步骤的错误会传播到后续步骤，导致级联错误。一旦推理链在某一步出错，后续所有步骤都基于错误的前提进行推理。这也是 Self-Consistency (Wang et al., 2022) 等后续工作试图解决的问题 -- 通过采样多条推理链并投票来缓解单链错误。

不适用场景
CoT 在以下场景表现不佳：（1）纯知识检索题（不需要推理的事实问答）；（2）创意生成任务（诗歌、小说等）；（3）小模型部署环境；（4）对延迟极度敏感的实时应用。Agent 设计者需要根据具体场景决定是否启用 CoT。

与斯坦福小镇的关联：CoT 是 Agent 推理的隐形基石

Chain-of-Thought 虽然不是 Generative Agents 论文中显式引用的技术，但它是整个 Agent 系统运作的隐形基础设施。

规划模块中的 CoT

斯坦福小镇的 Agent 每天早晨生成日程计划时，实际上在执行一种隐式的 CoT：

  • "我是 John Lin，一名药房店员" → 思考角色身份
  • "今天是工作日" → 推断需要上班
  • "我通常8点起床" → 结合习惯
  • "所以今天的计划是：7:00起床, 8:00出门, 9:00到药房..." → 逐步生成计划

这种"先推理背景，再生成行动"的模式正是 CoT 的具象化。

反思模块中的 CoT

当 Agent 进行 Reflection 时，需要从多条记忆中归纳出高层洞见。这个过程本质上是一个多步推理：

  • 检索相关记忆片段 → 识别共同主题 → 抽象为更高层次的理解 → 生成反思语句

没有 CoT 能力，模型无法完成这种递进式的归纳推理。

对话生成中的 CoT

当两个 Agent 对话时，模型需要考虑：对方是谁、我和对方的关系、当前情境、我的性格特点... 然后才生成回复。这种多维度的上下文整合也依赖 CoT 能力。

CoT 是 Agent 能力的下限
可以说，LLM 的 CoT 能力决定了基于 LLM 的 Agent 系统的推理能力上限。CoT 越强，Agent 的规划、反思、对话能力就越强。这也解释了为什么斯坦福小镇选择 GPT-3.5/4 这样的大模型 -- 只有足够大的模型才具备支撑 Agent 复杂行为的 CoT 能力。
CoT 是 Generative Agents 中规划（Planning）和反思（Reflection）模块的推理基础。Agent 的"想清楚再做"本质上就是 CoT。规划模块生成日程时的逐步分解、反思模块总结记忆时的递进推理都依赖 CoT 能力。如果将小镇 Agent 的底层模型替换为一个没有 CoT 能力的小模型，整个系统的行为质量将急剧下降 -- 这正是 CoT 作为"隐形基石"的角色所在。
