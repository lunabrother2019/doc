一句话定位：用 1000 万条"真人画像"初始化社会仿真

SocioVerse 是复旦大学 DISC 实验室（Zhongyu Wei 课题组）提出的社会仿真世界模型。它的核心论断只有一句：想让大模型预测真实社会行为，就必须用真实人口数据对齐它——而不是让研究者手搓几十个 persona。 为此作者从 X（推特）和小红书抓了 1028 万条真实用户的历史发帖，用 LLM 标注 + 人工核验 + 分类器训练的方式把年龄、性别、职业、种族、收入、教育等 15 个维度都打上标签，形成一个"可随机抽样初始化 Agent"的真人池。

关键创新：真实用户画像 vs 小镇的手写 persona

小镇的"persona 瓶颈"

回看 2023 年的 Generative Agents (arXiv:2304.03442)：Smallville 里的 25 个居民，每个人的性格、职业、家庭关系都是研究者用一段自然语言 seed memory 手写进 prompt 的。比如：

小镇 persona 范例（简化）： Name: John Lin Age: 45 Occupation: Pharmacy shopkeeper Personality: Friendly, hardworking, loves family Seed memory: John lives with his wife Mei and son Eddy...

这种"作者神 (author-god)"方式的优点是可控、可读，缺点是：完全依赖研究者的想象力，25 个人不足以构成有统计意义的总体，样本既不多样也不真实，没法做"美国大选会怎样"这类需要对齐真实人口分布的问题。

SocioVerse 的换法：从真人身上反推 persona

关键转向
不再写"一个典型中年药店老板"，而是直接拿一千万条真实用户的历史帖子，让每个 Agent 都是对一个具体真人的画像复刻：帖子文本 + 15 维人口标签共同构成 persona，抽样时按真实人口分布按需调用。

两者差异一览

维度小镇 (Park 2023)SocioVerse (2025)
Persona 来源研究者手写自然语言种子1000 万真实社媒用户
规模25 人（单镇）10M 用户池，实验单次抽样 16K–331K
人口分布对齐无，靠作者经验IPF + 人口普查/ANES 先验
目标任务涌现社会行为、叙事连贯预测真实公共议题反应
可验证性定性（参议员选举、情人节派对）定量（大选 RMSE / 消费 KL 散度）
领域迁移需要重写世界复用模板，换用户+换场景
为什么这很重要
把社会仿真从"讲故事"带入"做预测"。小镇证明了 LLM Agent 能涌现出像样的社会行为；SocioVerse 则在问——能不能像天气预报一样预测社会行为？答案是"至少在 2024 大选上能做到 92.2%"。

架构四件套：世界模型的四层对齐

SocioVerse 把社会仿真拆解为四个 alignment 维度，每个维度配一个引擎。这是论文的核心贡献之一——把"世界模型"这个虚词变成了可复用的四件套组件。

① Social Environment（社会环境）
注入三类现实上下文：
• 社会结构：人口分布、文化规范。
• 社会动态：时效性新闻、政策事件。
• 个性化上下文：推荐 feed、关注列表。
解决"LLM 静态知识与动态世界错位"的问题。
② User Engine（用户引擎）
10M 真人池：X（1M 用户 / 3000 万帖）+ Rednote（920 万用户 / 4100 万帖）。
经"LLM 标注 → 人工核验 → 分类器蒸馏"打上 15 维人口标签（年龄/性别/职业/收入/教育等），LongFormer 给英文、BERT-base-chinese 给中文。
③ Scenario Engine（场景引擎）
把"交互结构"抽象成四种模板：
• Questionnaire：1-to-N（一题多人答）
• Interview：1-to-1 深访
• Behavior Experiment：1-to-N / N-to-N
• Social Media Interaction：N-to-N
让同一框架能插拔不同实验。
④ Behavior Engine（行为引擎）
混合两类 agent：
• 规则型 Agent：高并发、低成本，用在消费记账这类可结构化行为。
• LLM Agent：复杂推理，用在态度生成 / 新闻评论等。
通用/专家/领域三类模型按需切换。

形式化：仿真的总体目标

SocioVerse 世界模型的抽象公式（作者意图的重构）： Response_sim = f_behavior( f_env(E, t), # 环境对齐 sample(UserPool | π_demo), # 用户对齐 template(scenario_type) ) # 场景对齐 其中 π_demo 由 IPF / IDS 从真实人口边际分布重建

这四件套的野心是"像软件 SDK 一样可复用"——换个国家、换个议题，只需要替换 UserPool、scenario template、environment feed，behavior engine 主体不动。

现实状态
论文自己承认："当前版本只实现了框架的一部分"——意味着 Scenario Engine 的四类模板并非都已在实验中完整验证，Social Media Interaction（N-to-N）部分实现细节较少。未来版本补全

校准 Pipeline：IPF + 先验分布 + 分类器蒸馏

SocioVerse 的工程灵魂在校准——如何从"有偏采样的社媒用户"推到"人口统计意义上的真实样本"。作者的 pipeline 分三步。

Step 1：用户池构建 & 清洗

1
抓取：X 和 Rednote 用户的公开发帖，时间跨度未完全披露。具体窗口
2
反机器人/反广告：用文本相似度（重复率 0.3 阈值）过滤 bots 和推广号。
3
活跃度过滤：保证每个用户有足够历史内容可以反推画像。

Step 2：15 维人口学标注（弱监督 + 蒸馏）

  1. LLM 标注：用 GPT-4 / Qwen 级模型读取用户帖子，输出 15 维标签。
  2. 人工核验：小样本人工抽检作为 gold set，评估 LLM 标注准确率。
  3. 分类器蒸馏：用 LLM+人工结果作为训练集训 LongFormer（英文）/ BERT-base-chinese（中文），批量推到 10M 规模。这是 SocioVerse 能扩展到千万级的工程关键。
为什么要分类器蒸馏
直接用 LLM 标 1000 万条要烧掉天量 token。把 LLM 标注作为"教师"训练一个专用分类器作为"学生"，推理成本下降 2–3 个数量级，让千万级人口池从 PoC 变成可维护资产。

Step 3：IPF 迭代人口比例拟合

构建好用户池后，抽样阶段需要让样本分布匹配目标人口（如"美国合格选民分布"或"上海常住人口分布"）。SocioVerse 用的是经典统计方法：

  • IPF (Iterative Proportional Fitting)：给定年龄、性别、地区等若干边际分布，迭代拟合出满足所有边际约束的联合分布。人口普查不会告诉你"30 岁女性纽约居民"的具体比例，但会告诉你"30 岁"、"女性"、"纽约"的独立边际；IPF 把这三个边际"缝合"成联合。
  • IDS (Identical Distribution Sampling)：一旦联合分布计算好，直接按它从用户池里抽人。
  • 先验源：美国用 Census + ANES（美国全国选举研究）；中国用国家/地区统计年鉴；消费实验用地区收入分布。
IPF 迭代骨架（伪代码）： P(age, gender, region) ← 均匀初始化 repeat: 对 age 维度 归一化到 P_census(age) 对 gender 维度 归一化到 P_census(gender) 对 region 维度 归一化到 P_census(region) until 收敛
消融发现
论文的 ablation 明确显示：去掉先验分布或去掉真实用户历史帖，预测准确率显著下降。这给"世界模型 = 真实数据先验"这个论点提供了直接证据——仅凭 LLM 的参数知识是不够的。
5

三大实验：政治 / 新闻 / 经济

SocioVerse 选了三个议题类型截然不同的场景做验证，覆盖"有标准答案"（大选、消费）和"无标准答案但有分布"（新闻情感）两类。

实验一：2024 美国大选预测（政治）

项设计
样本~331K Agent，按美国合格选民人口分布抽样
环境注入候选人信息、选情新闻
任务每个 Agent 投票 → 州级汇总 → 选举人团计算
指标州级预测准确率 / 得票率 RMSE
结果Qwen2.5-72B 达 92.2% 准确率，10 个摇摆州命中 8 个

这是整篇论文最亮眼的单点成绩。和传统民调相比，SocioVerse 不需要打电话和付费招募，复现成本极低、可以反复跑"假设性扰动"（比如"如果某政策出台会如何影响"）。

实验二：ChatGPT 发布的新闻情感（突发事件）

项设计
样本~20K Rednote 用户（tech 兴趣人群）
任务ChatGPT 发布时公众态度预测
心理学模型ABC：Affect（情绪）/ Behavior（行为倾向）/ Cognition（认知）
指标6 维 Likert 量表上的 NRMSE + KL 散度
结果GPT-4o 与 Qwen2.5 与真实用户反应高度一致

这个实验把社会心理学的 ABC 模型嵌进了 prompt——让 Agent 不只回答"好/坏"，而是分别给出情绪、行为倾向、认知判断。这种结构化输出比自由文本更容易做定量评估。

实验三：中国居民消费结构（经济）

项设计
样本~16K Agent，按区域人口和收入分布抽样
任务预测 8 类支出（食品 / 居住 / 医疗 / 教育 / 交通 / 通信 / 娱乐 / 其他）
指标每类支出的 NRMSE + 整体 KL 散度
结果Llama3-70B 整体表现最佳；日常品类准确度高，住房相关预测偏差较大
有意思的失败模式
住房经济表现不好——作者分析原因：LLM 的训练语料里"买房/房租占收入比"这类需要地域性专业知识的内容权重不足，导致 Agent 对高房价城市的估计偏低。这提示了纯 LLM+persona 路线的天花板。

跨实验的发现

  • 模型不是越大越好：不同领域最优模型不同（Qwen2.5 强在政治、Llama3-70B 强在消费、GPT-4o 强在情感）。
  • 系统性"不同意偏差"：LLM Agent 倾向于比真人更频繁给出"不同意 / 不选择"，需要专门 debias。
  • 人口先验的边际价值递减：从"无先验"到"边际分布先验"提升显著；从"边际"到"联合"提升有限。

哲学定位：三条对 persona 的不同假设

  • Park 2023（小镇）：Persona 由作者写就，LLM 负责让它"活起来"。
  • Park 2024（1000 Agents）：Persona 必须来自高保真个人访谈，2 小时深访比任何 demographic 标签都重要。
  • AgentSociety：Persona 是合成的但人口分布正确的，不追求个体高保真，追求群体代表性。
  • SocioVerse：Persona 来自真人数字痕迹——不是访谈（贵）也不是合成（假），而是"社媒历史帖 + 人口标签"的折中路线，然后用 IPF 保证抽样分布对齐。
关键洞察
四者不是替代关系而是谱系关系：小镇重叙事、Park 2024 重个体保真、AgentSociety 重群体动力学、SocioVerse 重公共议题的预测校准。选哪条路取决于你问的是"社会会演化成什么样"还是"今天的美国会投给谁"。
SocioVerse 相当于给小镇的 Memory Stream 换了一个"来源"：不再是剧作家构造的虚构经验，而是真实个体在社交媒体上留下的数字影子。小镇的架构本身可以不变——变的是 seed memory 的统计真实性。

代码仓库实证：GitHub 上到底有什么

⚠️ 核心结论：这不是完整实现，是数据+评估壳
截至 2026-04-20，FudanDISC/SocioVerse 仓库（175 stars / 14 forks，最后更新 2026-02-08）没有任何仿真执行代码。论文核心——World Model 四大 Alignment 模块的实现标注 "coming soon"，至今未发布。仓库仅包含评估脚本、问卷定义和样本用户数据。

7.3 评估脚本做什么

三个评估脚本实现的是事后验证逻辑——不是仿真执行逻辑，它们读取由外部系统（未开源的 World Model）生成的结果文件，然后和 ground truth 比较：

1
electionSim_evaluation.py — 读取 final_output.jsonl，按 ANES 调查问卷编码（如 V201007a）统计 Democrat/Republican 投票比例，对 51 州逐一与真实选举结果比较 → 计算 RMSE + 州级准确率。这就是 "92.2% state-level accuracy" 的计算方式。
2
ecoSim_evaluation.py — 读取模拟消费支出，对比中国统计局月度数据，计算 KL Divergence + RMSE。支持 GPT-4o / GPT-4o-mini / LLaMA3 / Qwen2.5 / DeepSeek-R1 五个模型对比。
3
pressSim_evaluation.py — 极简脚本，对新闻反馈场景计算 RMSE + KL Divergence。

7.4 从评估代码逆推仿真流程

虽然仿真代码未公开，但从问卷结构和评估脚本可以逆向推断执行流程：

①
Sampling — 根据场景从千万池中按 overlap_score / similarity 抽样代表性子集（IPF 加权）
②
Profile Construction — 用人口统计标签 + 用户发帖文本构建 Agent persona prompt
③
Survey Simulation — 将标准化问卷（ANES 选举调查 / 消费支出问卷）发给 LLM，角色扮演为该用户回答
④
Aggregation — 汇总所有 Agent 回答，统计群体分布 → 输出 final_output.jsonl

第 6 节对照表"代码"行写了"开源 FudanDISC/SocioVerse"。严格来说这个描述有误导性——仓库确实是 Apache 2.0 许可证公开的，但核心仿真实现完全缺失。与 Smallville（完整可运行的 agent 循环）和 AgentSociety（完整 pip 包）相比，SocioVerse 的开源程度远低于表中暗示的水平。其真正公开的有价值资产是用户画像数据集和评估方法论，而非仿真框架本身。
这个代码现状再次印证了社会仿真领域的普遍问题：数据比代码更有壁垒。SocioVerse 的真正护城河是那 1000 万条有标签的真人画像——评估脚本和仿真循环是可复现的工程工作，但这个量级的标注数据不是。如果要在自己的项目中复用 SocioVerse 的思路（真人池 + IPF 抽样 + LLM 角色扮演），其用户池数据（HuggingFace 上的 user ID + 标签）是最有直接价值的部分。

FAQ

Q1. 为什么不像 Park 2024 那样做真人访谈？1000 人就够了，真的需要 1000 万吗？
两条路线解决不同问题：
  • Park 2024 做的是"个体保真"——能不能让 Agent 在认知/态度问卷上复刻具体某个真人 Alice 的回答？2 小时访谈 ≈ 读懂一个人的信念结构。
  • SocioVerse 做的是"总体代表性"——能不能让 10 万个 Agent 的群体回应复刻"美国所有选民"？这要求样本覆盖人口分布的每个角落，只有 10M 量级的用户池才能在按 IPF 抽样时保证每个人口格子里都有足够可选样本。
一句话：访谈追求深度，SocioVerse 追求广度。做大选预测必须广；做个体心理研究必须深。
Q2. "LLM 标注人口属性"本身会不会有严重偏差？比如把大学生都猜成城市人？
这是数据流水线里最危险的一环。SocioVerse 的三重防御：
  • 人工核验：小样本金标集评估 LLM 标注准确率，论文公布了不同维度的 accuracy（但具体数字分布未完全披露）。各维度 accuracy 明细
  • 分类器蒸馏的正则效应：LongFormer / BERT 学不到 LLM 里的长尾噪声，相当于给标签"退火"。
  • IPF 在后处理：即使单个用户的标签有误，只要群体上与人口普查对齐，抽样后的统计意义依然成立。
但坦率地说，这条流水线的系统性偏差（比如少数族裔在社媒声量不足）仍是未解难题。论文也承认住房类经济预测偏差较大，部分原因就在于社媒群体不代表全社会。
Q3. 和斯坦福小镇相比，SocioVerse 能跑"涌现社会行为"（比如自发举办派对）吗？
不能，或者说没被设计来做这件事。
  • 小镇的任务形态是开放式多轮互动：Agent 自己规划、相遇、聊天、回忆、反思，产生"派对"这种非脚本事件。核心是长时序 + 多 Agent 耦合。
  • SocioVerse 的任务形态是结构化一次性作答：给定问题（投票/态度/支出），Agent 按模板给答案，再做群体聚合。没有 Memory Stream、没有 Reflection、没有计划。
可以把 SocioVerse 视作"小镇的问卷版人口"：只用到了 persona + reasoning，没用到记忆/规划/反思。如果未来要在 SocioVerse 上跑涌现故事，需要把小镇的 Memory Stream 架构嫁接进 Behavior Engine，形成"10M 真人池 + Memory 栈"的融合体——这可能是这条研究线下一个里程碑。
