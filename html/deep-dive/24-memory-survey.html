为什么需要这篇综述：Agent 记忆研究的"碎片化"困境

2023 年以来，"给 LLM 加记忆"几乎成为 Agent 方向的标配课题：从 MemGPT、Mem0、A-MEM 到 MemoryOS，从 LongMemEval 到 LoCoMo，从 HippoRAG 到 Zep ——数十个系统、十几个评测、几十种术语同时涌现。但这股繁荣的副作用是：研究动机、实现方式、评测协议几乎没有公共语言，传统的"长期/短期记忆"二分法已经完全不够用。

核心贡献一：清晰划定 Agent Memory 的边界

这一节是综述最"政治性"的一章——划清楚"什么才算 agent memory"。不设边界，讨论就不可能收敛。

概念 存放在哪里 典型载荷 写入谁来决定 与 Agent 关系
LLM Memory 模型权重 / KV-cache 训练语料中的通用知识、上下文窗口内的 token 训练时由预训练/微调决定；推理时由输入决定 Agent 的"底层记忆"，不是 agent 可主动管理的对象
RAG 外部向量库 / 文档 静态知识库（维基、企业文档） 系统离线索引，对 agent 的运行史只读 是检索通道，默认不记录 agent 自己的经历
Context Engineering prompt 模板 / 上下文槽位 指令、few-shot、工具描述 开发者 / 调用方 手工拼装 是"记忆使用方式"的工程层，不产生新记忆
Agent Memory 外部结构化/向量 + 可选参数 agent 自己 的经历、反思、偏好、工作草稿 agent 自身在运行中读写 让 agent 跨会话持续成长、可追溯、可进化
关键判定准则

一个记忆系统是不是 "agent memory" 的判据不在"长/短"，而在 "是否是 agent 在运行中生成并再次利用的东西"。按这个标准：RAG 接企业 wiki → 不是；Smallville 的 memory stream 记录小镇居民今天谁跟谁吵架 → 是。

核心贡献二 · Forms（形态）：记忆"存在哪一层"

综述提出三种 Agent Memory 的物理实现形态。这一维度回答的是："这段记忆到底是 一串 token、一组权重、还是 一个隐向量？"

① Token-level Memory（显式文本记忆）

以自然语言文本 / JSON / 结构化表格的形式保存，放在向量库、知识图谱、文件系统里。检索后回填到 prompt。

代表：Smallville Memory Stream、MemGPT、Mem0、A-MEM、MemoryOS、Memori、Zep。优点：可解释、可编辑、可审计；缺点：上下文带宽受限，每次检索都要"花 token"。

② Parametric Memory（参数化记忆）

把经验压缩进模型权重/适配器（LoRA / 增量微调 / edit），运行时"自然"产出而不必检索。

代表：持续学习型 agent、knowledge editing（ROME / MEMIT）、personalised LoRA。优点：零检索成本；缺点：难追溯、难删除，与 GDPR "被遗忘权" 紧张。

③ Latent Memory（隐空间记忆）

把记忆编码成连续向量 / soft prompt / cache state，以 KV-cache、外部 hidden state 或 retrieval-augmented parameter 的形式参与推理。

代表：RMT、Memorizing Transformers、Recurrent Memory、部分 agent 的 latent plan buffer。优点：带宽高、与模型融合深；缺点：不可人读、不可跨模型迁移。

新视角：形态不是对立，而是频谱

综述强调这三种形态 常常同时存在于同一个 agent。例如 MemoryOS 同时含 token-level 的长期画像 + latent 的短期 KV 缓存；未来系统可能把"近期"放 latent、"中期"放 token、"终身"压入参数。

4

核心贡献三 · Functions（功能）：记忆"用来做什么"

比起传统"长短期"划分，功能维度更能反映 agent 真实使用场景。综述把 agent memory 细分为三类：

功能类别 定义 典型内容 典型系统 代表性用途
Factual Memory
事实记忆		 关于"世界 / 用户 / 实体"的静态或慢变事实 用户偏好、人名、地址、业务术语表 Mem0、Memori、Zep（graph 部分） 跨会话个性化、客服一致性
Experiential Memory
经验记忆		 agent 在过去任务/对话中 做过什么、学到什么 的历史 对话历史、行动轨迹、反思、工作流成败案例 Smallville Memory Stream、Reflexion、A-MEM、Voyager skill lib 长期成长、失败规避、经验复用
Working Memory
工作记忆		 当前任务在进行时的 中间草稿/中间状态 子目标栈、当前工具调用中间结果、暂存思考链 HiAgent、MemGPT 的 main context、plan-and-solve 的 scratchpad 多步推理、子任务协调
为什么这个三分法重要

同一段文字在不同的三分位置上，生命周期、检索策略、遗忘规则完全不同： 事实记忆要去重 + 覆盖更新； 经验记忆要累积 + 反思升维； 工作记忆要任务结束即清空。 把三者混在一个 vector store 里是目前很多开源方案的隐性 bug。

Smallville 的 memory stream 在综述分类里同时落在 经验记忆（对话、事件、反思）和一部分 工作记忆（当日计划的中间状态）；事实记忆则被"藏"在初始 seed memory 里。这解释了为什么小镇原文需要 recency/importance/relevance 三重评分才能跑起来：它在一个池子里同时服务了两种不同功能。

核心贡献四 · Dynamics（动态）：形成 → 演化 → 检索

一段记忆不是"出生即死亡"的静态物。综述把记忆的生命周期拆成三个阶段：

阶段 1

Formation 形成

从原始交互中筛选、压缩、抽取。涉及：重要性评分、LLM 重写、实体抽取、embedding 生成、自动打标签。
类比：人类"编码"阶段

→
阶段 2

Evolution 演化

记忆不是 append-only：反思、合并、升级、遗忘。A-MEM 的关联建边、MemoryOS 的页换出、Memori 的冲突消解都属于这一层。
类比：人类"巩固 + 遗忘曲线"

→
阶段 3

Retrieval 检索

为当前 query 找出最相关、最新、最重要的记忆。涉及：向量相似、图遍历、recency/importance 加权、结构化过滤。
类比：人类"提取"阶段

动态维度下各系统的侧重

系统 Formation 亮点 Evolution 亮点 Retrieval 亮点
Smallville LLM 打重要性分 (1–10) 反思：阈值触发升维 0.5·rec + 0.3·imp + 0.2·rel
MemGPT / Letta 对话转档：main ↔ archival OS 式分页、page-in/out 函数调用式检索
A-MEM 写入时即生成 tag + keywords Zettelkasten 自动建边 向量 + 链接扩展
MemoryOS 分段写入 dialogue chain 三级 FIFO 淘汰 + 分页 从用户画像 + 近段话题混合召回
Mem0 LLM 抽取 facts 并去重 冲突时"覆盖 / 合并 / 忽略"三选一 过滤式向量检索
Zep (Graphiti) 时序知识图 + 实体解析 版本化事实（temporal validity） 图遍历 + 时间窗
这篇综述带来的新视角

以前大家讨论"哪个记忆系统更好"基本不对等——Mem0 强在 formation（抽取/去重）；A-MEM 强在 evolution（建边）；MemoryOS 强在 retrieval（分层调度）。它们本质在三个不同阶段互补，不是互相替代。综述给了一个可以"分层比较"的公共尺子。

未来方向：作者视角下的 Agent Memory Frontier

综述结尾列出五条值得重点投入的研究方向，每一条都已经能在本库看到早期萌芽：

① Memory Automation（记忆自动化）

目前记忆策略（写什么、何时反思、何时遗忘）大多是人工规则 + 阈值。未来：让 agent 自己学会"如何管理自己的记忆"——把 memory management 本身做成一个可学习策略。

② RL Integration（强化学习集成）

用 RL 来优化检索策略、写入时机、遗忘阈值，让任务反馈信号反向调参记忆模块。与 Voyager 的技能获取、Reflexion 的反思机制天然契合。

③ Multimodal Memory（多模态记忆）

记忆不限于文本：图像、音频、视频、传感器流都应可被 agent 主动记录。挑战：跨模态的检索、摘要与"重要性"评分。

④ Multi-Agent Memory（多智能体记忆）

小镇已经有雏形——agent 间可以共享、互传、互相污染记忆。综述提出需要系统研究"共享层级、访问控制、信任链"。

⑤ Trustworthiness（可信：隐私 / 遗忘 / 防攻击）

参数化记忆与 GDPR 被遗忘权冲突；记忆投毒（memory poisoning）是新型攻击面；长期持久的 agent 甚至会记住不该记住的信息。需要显式的遗忘机制、访问控制、审计日志。

跨方向串联的预测

综述隐含的一个判断：①②（自动化 + RL）会最先突破，因为它们本质是"闭环优化"问题；③④⑤则需要新的评测基础设施。对工程社区而言，现在投入 自动化 + 可信两条是性价比最高的。

与 Generative Agents / 斯坦福小镇的系统性映射

把小镇的 memory stream 放进综述的三维坐标里，可以看得更立体：

小镇组件 Forms Functions Dynamics 综述视角下的评价
Memory Stream（主日志） token-level 经验记忆为主，工作记忆为辅 Formation（LLM 打分）+ Retrieval（三重加权） 代表性完整实现，但没有显式遗忘
Reflection（反思） token-level 经验记忆升维 Evolution：阈值触发 + LLM 综合 综述中 evolution 的经典范例
Plan（当日计划） token-level 工作记忆 短生命周期，当日写入、当日消费 按综述应独立成池而非与事件混放
Seed Memory（初始画像） token-level 事实记忆 Formation 前置，几乎无 evolution 相当于"冷启动 fact store"
评分公式 0.5·rec + 0.3·imp + 0.2·rel — — Retrieval 阶段 属于综述"检索动态"中最早的多因子融合样板

如果要给小镇做"综述视角下的体检报告"：
· 优点：覆盖三阶段 dynamics；memory stream 概念开创性；反思机制即 evolution。
· 短板：没有显式遗忘（evolution 不完整）；事实/经验/工作记忆混放在一个池子（functions 没分层）；纯 token-level（forms 单一）；benchmark 上会被新一代系统反超。
这正是为什么 MemoryOS、A-MEM、HiAgent 三条技术路线都值得同时吸收——它们分别在 dynamics 的 retrieval、dynamics 的 evolution、functions 的工作记忆 三个维度上各补了小镇的一块短板。
