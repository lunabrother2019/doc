问题与动机：长程任务的上下文爆炸

ReAct 式 Agent 的经典范式是把 Thought → Action → Observation 的完整历史线性堆进上下文。对于 5–10 步的短任务这没问题；但是当任务要 30、50、100 步时，问题立刻暴露：

  • 上下文线性膨胀：每一步都把之前所有步骤再读一遍，token 成本 O(N²)
  • 信息稀释：关键早期线索被海量无关观察淹没，LLM 注意力被拖垮
  • 缺乏任务分解感：模型看到的是流水账，没有"当前阶段"和"已完成阶段"的层级概念
HiAgent 的核心观察
人类解决长程任务时，不会记住每一个动作细节，而是把任务切成子目标（subgoal），每完成一个就把过程压成结论（"我已经把木头砍够了"），只留下对后续有用的信息。HiAgent 把这个模式形式化为 LLM Agent 的工作记忆管理策略。

核心机制：双层工作记忆

HiAgent 把 Agent 的工作记忆明确切成两层，这是它与 ReAct / Reflexion 最根本的结构差异。

高层：Subgoal Stack（子目标栈）

作用：全局导航

  • 任务开始时，LLM 被 prompt 要求先生成一个初始子目标（而不是直接决定第一个 action）
  • 每次 LLM 推理都先看到"当前子目标 = X"作为锚点
  • 完成后的子目标会被"封存"成一行摘要，留作历史记录
  • Agent 可以随时决定 replace subgoal：发现当前子目标做完了或不合适，就切到下一个

底层：Action-Observation Window（行动-观察窗口）

作用：局部细节

  • 只保留与当前子目标相关的 (action, observation) 对
  • 子目标切换时，上一个子目标下的所有原始观察被丢弃或压缩成一句摘要，不再占用上下文
  • 这让 LLM 的"工作记忆"始终聚焦在当下阶段，避免被 50 步前的无关操作干扰
关键动词：proactive replacement
HiAgent 让 LLM 主动决定何时"结案"一个子目标。这不是外部触发器，而是融进 prompt 的一个 action 选项 —— 模型每一步都可以选择"继续执行当前子目标"或"更新子目标"。这是把记忆管理权交给 Agent 自己的关键设计。

算法流程：一步一步看

HiAgent 主循环（简化） state ← task_description subgoals ← [] # 已封存子目标摘要 current_sg ← LLM.propose_subgoal(task) window ← [] # (action, obs) pairs while not done: prompt = format(task, subgoals, current_sg, window) decision = LLM(prompt) if decision.type == "update_subgoal": subgoals.append(summarize(current_sg, window)) current_sg = decision.new_subgoal window = [] # 丢弃旧窗口 else: action = decision.action obs = env.step(action) window.append((action, obs))

注意两点设计精巧:

  1. subgoals 是摘要列表而非原始日志 —— 高层只存"结论"，空间常数级增长
  2. window 每次切子目标就清空 —— 底层不随任务长度增长而膨胀

这两点联合保证了：无论任务多长，LLM 每次看到的 prompt 长度都近似常数。这就是 HiAgent "解决上下文爆炸"的全部秘密。

Prompt 结构示意

# Task
{task_description}

# Completed Subgoals (摘要)
[SG1] 找到厨房的钥匙 ✓ (从客厅抽屉里拿到)
[SG2] 打开厨房门 ✓

# Current Subgoal
[SG3] 在冰箱里找到牛奶

# Recent Actions (仅当前子目标)

HiAgent 是 "结构化压缩" 的最简可行方案 —— 没有引入图结构、也没有复杂的淘汰策略，只用一个"子目标栈 + 当前窗口"就把长程任务的上下文成本压到常数。它的贡献不在复杂度而在把记忆管理权显式交给 LLM 自身，这个思路后来被 A-MEM / MemoryOS 等复杂化方案继承。

与斯坦福小镇的关联

Smallville 的 Memory Stream 是扁平的 —— 所有记忆按时间戳排队，通过 recency × importance × relevance 三元打分检索。这套机制在 25 个 Agent 的小镇里工作得很好，但有两个未显式暴露的前提假设：

  • 单个 Agent 的生命周期不长（仿真天数有限）
  • Reflection 机制会把老记忆压缩成高阶洞察，缓解膨胀

HiAgent 相当于把小镇隐式依赖的这个"压缩通道"显式化并放大：

维度 Smallville Memory Stream HiAgent 双层记忆
结构 扁平时间序列 显式双层（子目标栈 / 当前窗口）
压缩触发 重要度阈值驱动 Reflection 子目标完成驱动 summarize
压缩粒度 高阶洞察（语义抽象） 阶段结论（任务导向）
上下文占用 检索后 top-k 拼接，仍有膨胀压力 近似常数
适用场景 开放式社交仿真 目标导向长程任务
HiAgent 可以看作 Memory Stream 的任务版：小镇处理"过去一天我做了什么"，HiAgent 处理"为了达成目标我做了什么"。两者的核心洞察一致 —— 记忆必须分层、必须压缩、必须让 Agent 自己决定何时压缩。如果把 HiAgent 的子目标栈替换成"日程表"，它的结构就几乎重合于小镇 Agent 的 daily plan + recent actions 组合。这也是为什么在 architecture-study.html 里我们把 HiAgent 列为 Claude Code 三层自愈记忆的理论先驱之一。
