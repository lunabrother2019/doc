LLM Agents Suffer from Hallucinations — Agent 幻觉系统综述 后加

深度解读：当 Agent 从"纯 LLM 对话"进化为"感知 → 推理 → 规划 → 记忆 → 工具 → 通信"的多模块系统，幻觉也从"一句话编造"升级为 跨阶段、跨模块、可传播、物理后果不可逆 的复合现象。本综述首次把 Agent 幻觉拉成一张完整的"五阶段 × 十八成因"地图。

一句话定位：Agent 幻觉不是"LLM 幻觉 + Agent 壳"，而是全新的复合病灶

过去两年关于"LLM 幻觉"的综述已经有十余篇，但它们讨论的本质是 "一句话对不对"——事实性（factuality）与忠实性（faithfulness）。然而 LLM-based Agent 把模型包进了一个多模块闭环（感知—推理—规划—记忆—工具—通信），幻觉不再是一次 forward pass 的错误，而是跨模块、跨时间步的"链式污染"。

综述的核心主张（原文精炼）

"Agent hallucinations are compound behaviors arising from interactions among multiple modules, with propagation chains across multiple steps, and physically consequential errors in real-world systems."
—— 与纯 LLM 幻觉的区别不是程度，而是 拓扑：它发生在图（多模块 DAG）上，不是在序列（token stream）上。

与传统 LLM 幻觉综述的三点区别：

  • 按"阶段"组织而非按"事实/忠实"两分——承认 Agent 的内部状态比 LLM 多得多（环境观测、工具返回值、记忆检索结果、多 agent 通信）。
  • 承认"物理后果"——Agent 往往驱动真实工具（API 调用、文件操作、机器人手臂），幻觉不再只是"说错话"而是"做错事"。
  • 引入"传播"视角——一个上游模块的小幻觉，可能在下游被规划器采纳、被记忆固化、被通信广播，形成雪球。

综述的幻觉分类体系：五阶段 × 十八成因

综述以 Agent 完整工作流 为骨架，把幻觉按 "发生在哪个阶段" 一刀切开，共五大类，每类下各有 2–3 个子型；再配 18 个触发成因。以下是完整展开。

2.1 五大类幻觉概览

阶段 1

Reasoning 推理

理解目标、分解意图、生成计划。典型病症：看起来合理但逻辑错误、子目标不相关、漏掉关键约束。

→
阶段 2

Execution 执行

选择工具、传参调用。典型病症：调用不存在的工具、捏造参数值、声称执行完成实则未动作。

→
阶段 3

Perception 感知

对环境观测的内部表示。典型病症：看到了不存在的物体、忽视了真实对象、跨模态对齐错误。

→
阶段 4

Memorization 记忆

检索/写入记忆。典型病症：召回无关事实、把错误信息当真记下、更新时误删正确记忆。

→
阶段 5

Communication 通信

多 agent 间消息传递。典型病症：agent A 捏造事实说给 agent B，B 当真并继续传播。

2.3 十八触发成因（按阶段归类）

Reasoning 推理阶段（5 因）

  1. Problematic Objective Expression：用户输入目标不完整、含糊
  2. Inadequate Subjective Comprehension：指令跟随偏差、长程上下文误用
  3. Deficient Dependency Modeling：子意图间依赖关系建模不足
  4. Planning Information Misinterpretation：对可操作对象/自身能力边界的误解
  5. Planning Information Misapplication：逻辑谬误、内省能力不足

Execution 执行阶段（4 因）

  1. Tool Documentation Limitation：工具描述冗余/不完整/不规范
  2. Shallow Pattern Understanding：训练数据中工具使用场景不够多样
  3. Weak Dynamic Adaptability：无法应对工具版本变化、API 废弃
  4. Lack of Solvability Awareness：工具不可用/计划不完整时过度自信

Perception 感知阶段（2 因）

  1. Environmental Sensor Malfunction：相机/麦克风/测量单元的硬件失效
  2. Limited Encoding Capability：单模态表示不足、跨模态协同弱

Memorization 记忆阶段（4 因）

  1. Flawed Memory Initialization：基础记忆有偏/不完整
  2. Sub-optimal Retrieval Mechanism：排序/索引/语义理解差
  3. Imperfect Priority Assignment：遗忘/合并优先级判定错误
  4. Inaccurate Information Writing：压缩损失、格式不规范

Communication 通信阶段（3 因）

  1. Erroneous Message Propagation：事实性/忠实性幻觉在 agent 间扩散
  2. Uncoordinated Communication Protocols：异步调度错位、自然语言格式歧义
  3. Ineffective Network Updates：延迟的/不同步的 agent 间连接更新
为什么这个分类比"factuality / faithfulness"两分强

传统二分法把所有非事实陈述一锅端。综述的五阶段分类使得治理手段可以"对症下药"：感知幻觉应在视觉编码器/多模态对齐上改进，记忆幻觉应在检索/遗忘策略上改进，通信幻觉应在协议/共识机制上改进——完全不是同一类工程问题。

3

Agent 特有幻觉 vs 纯 LLM 幻觉：三种"新物种"

相较于传统 LLM 幻觉综述（如 Ji et al. 2023 那一代），本综述真正新的贡献是识别出只有 Agent 才会犯的三大类幻觉。这些在纯 LLM 里"不存在"，因为纯 LLM 没有循环、没有工具、没有持久记忆。

维度 纯 LLM 幻觉 Agent 特有幻觉 Agent 特有的根因
时间尺度 一次 forward 跨多轮、多 episode 状态循环 / 记忆持久化
输入空间 仅 token token + 环境观测 + 工具返回 感知/执行模块引入新噪声
错误放大机制 一次采样即终止 反馈回环累积、跨 agent 传播 闭环结构
典型可观测后果 错误回答 错误动作（改文件、发邮件、下订单） Agent 接入了真实 effector
可检测性 事后比对事实 需追溯多模块日志，"归因"困难 模块间耦合

3.1 循环带来的幻觉：Hallucination Accumulation

"雪球效应"——Agent 循环独有

第 T 步一个小幻觉（比如把某物体坐标记错 5 米）进入 状态 s_T，第 T+1 步的规划基于 s_T 产生"看似合理"的新动作，但其实是被污染的。经过 10 步 ReAct，原始误差可能被放大数十倍。综述把这类称为 Hallucination Accumulation，并指出"如何在多步推理中检测误差源"是未解决问题。

3.2 工具调用带来的幻觉：Fabricated Tool Invocation

这是纯 LLM 根本不会有的病症：

  • Tool Selection 幻觉：从工具库里挑了一个根本不存在的工具名（如发明 send_whatsapp_voice()）。
  • Tool Calling 幻觉：工具名对但参数捏造（如给真实的 book_flight 传一个查询不到的机场代码）。
  • Silent Success 幻觉：LLM 在没真正调用工具的情况下，凭"想象"生成了 tool 返回值并继续推理——这在 ReAct/Reflexion 里被多次观察到。
  • Solvability 盲区：任务本来就解不了（所需工具未注册），Agent 仍然自信地 "完成" 它。<待实证>：综述是否给出具体比例不详。

3.3 记忆带来的幻觉：Memory Poisoning & False Retrieval

这是本综述与 #24 Memory 综述 相互印证的重点：

  • 错误写入被固化：Reflexion/Reflection 把一条"其实错误"的反思写入长期记忆，之后每次检索都重复错误结论。
  • 检索语义漂移：向量检索召回"看起来相关但其实无关"的旧记忆，被 LLM 当成证据。
  • 遗忘失配：该忘的没忘（旧事实 override 新事实）、不该忘的忘了（重要偏好被换出）。
  • 记忆投毒：对抗场景下外部注入的 prompt 污染长期记忆；综述把这列为 Trustworthiness 未解决问题。
本综述与 #24 Memory 综述的交集

#24 Memory 综述在 Dynamics → Evolution 阶段批评"现有评测几乎不测遗忘/冲突消解"，而本篇则在 Memorization 幻觉里给出了 更精细的症状标签——两者合起来可以得到一张"Agent 记忆的失败模式×评测缺口"完整对照，是未来 benchmark 设计的关键依据。

缓解路径：三大分支 / 十余方法

综述把现有缓解工作拆成三条主线：知识利用（Knowledge Utilization）、范式改进（Paradigm Improvement）、事后验证（Post-hoc Verification）。每条线都可以在本库现有 deep-dive 里找到对应样本。

① 知识利用分支（外部 + 内部知识）

外部知识引导：

  • Expert Knowledge：引入知识库、规则约束（数学/语言学/程序学）、合成数据集
  • World Models：物理法则、社会系统知识；例如 NavMorph（环境知识）、WKM（常识知识）<待实证>：具体实现细节需查原论文

内部知识增强：

  • Prompt Engineering：CoT（思维链）、ToT（思维树）、constrained prompting（语义/空间约束）
  • Knowledge Editing：locate-and-edit、meta-learning（替换错误知识）
  • Knowledge Unlearning：参数优化、参数合并（删除错误内容）

② 范式改进分支（训练/学习结构创新）

  • Contrastive Learning：自监督区分"对/错"模式
  • Curriculum Learning：从简到难的任务序列
  • Reinforcement Learning：trial-feedback-adjustment 闭环优化策略（与 Reflexion 一脉相承）
  • Causal Learning：建模因果关系而非相关性
  • Graph Learning：把工具调用/记忆结构图化，降低规划幻觉

③ 事后验证分支（Self-correct / External Validator）

  • Self-verification：Agent 自己再生成一轮验证（对应 #10 Reflexion、Self-Refine 系列）
  • Validator Assistance：外部验证者/专家模型对输出做校准（对应 #16 MA-ToT Validator）

4.1 缓解路径 → 本库已读论文映射

综述的"治疗建议"小结

没有单一银弹：Reasoning 幻觉用 CoT + Self-verification；Execution 幻觉用 ReAct + 工具文档标准化；Memorization 幻觉用 RAG + 冲突消解 + 显式遗忘；Communication 幻觉用 Validator 或 共识协议。真正健壮的 Agent 必须是多层防御的组合，不是单一方法。

4.2 检测方法（相对缓解方法更不成熟）

  • Reasoning/Execution：逻辑一致性检查、工具可行性验证
  • Perception：传感器置信度评分、多模态一致性分析
  • Memorization：记忆一致性校验、检索相关性评分
  • Communication：消息准确性评估、协议符合性检查

综述明确指出：检测方法的成熟度远低于缓解方法——这也解释了为什么工业界部署 Agent 时常常"发生了幻觉但直到用户投诉才发现"。

对小镇用户模拟的警示：哪些机制会放大幻觉？

把综述的 5 阶段 × 18 成因映射回斯坦福小镇，会发现小镇的几个标志性机制恰恰是 幻觉放大器。这对"用 Generative Agents 做用户行为模拟"的研究者尤其重要——幻觉不是 bug，是被架构结构性放大的特征。

小镇机制 原始意图 被综述识别出的"幻觉放大路径" 对用户模拟的风险
Memory Stream 持久存储 保留所有经历，支持长期演化 一次错误观察/错误反思 → 进入 stream → 后续检索反复复现 错误信念会"在居民身上生根"，影响后续所有决策
Reflection 反思升维 把琐碎经历归纳成高阶洞察 Memory Update 幻觉：把错误前提归纳成"高可信度结论"，因为它看起来像洞察 模拟的用户画像会形成系统性偏差，越反思越自信错误
Inter-Agent 对话 居民互相交流、协作 Communication 幻觉：A 编造事实 → B 当真 → B 记入 memory → B 再传给 C "假消息在小镇里复制"——实验结论被污染
当日 Plan 分解 从粗到细生成行动链 Intention Decomposition + Planning Generation 幻觉叠加 居民计划"去不存在的地方做不存在的事"，仿真失真
retrieval = 0.5·rec + 0.3·imp + 0.2·rel 三因子加权召回 Memory Retrieval 幻觉：相似度假阳性 + 重要性误判 错误记忆以高分被召回，喂给下一次 prompt
综述 5 阶段在小镇里 全部 都出现：感知（对环境对象的解读）、推理（计划分解）、执行（action 指令）、记忆（stream 写读）、通信（agent 对话）。
更糟的是：小镇没有任何 显式验证器——没有 Validator agent，也没有外部 ground truth 对照。这等于把"无防御配置"推向大规模仿真，成因 #1（目标模糊）、#2（长程上下文误用）、#13（检索次优）、#16（消息传播）会联合发作。

5.1 小镇做"用户模拟"时最值得警惕的三条放大链

链 1：Perception → Memory → Reflection（内部污染闭环）

居民错误地把 Alice 的中性表情解读为"生气" → 写入 memory → 到阈值触发 reflection → 升维为 "Alice 最近情绪不稳定" → 作为高权重事实被反复召回。整个过程无人复核，对用户画像研究是致命的。

链 2：Communication → Memory → Communication（群体级放大）

居民 A 在对话中编造"Bob 要搬家" → Alice 信了写入自己 memory → Alice 跟 Carol 聊天时把它当事实再讲一遍。三步内，一个 A 凭空生成的消息变成社区共识。这是社会模拟实验最容易出现的污染路径，且非常像真实人类的谣言扩散——但问题在于这里是 LLM 编造的，不是仿真出的涌现现象。

链 3：Planning → Execution → Memory（行动污染）

计划"去图书馆"，但 action 调用到了不存在的 location → silent success 地"完成"（LLM 自填"我到了"）→ memory 里记录"今天去过图书馆"。之后居民相信自己去过图书馆，基于假经历规划后续行为。

给小镇/用户模拟研究者的实操建议
  1. 在 reflection 前插入 self-verification：每条高阶反思写入前，让 agent 再 check 一遍原始 memory 支撑。
  2. 给通信引入 validator：关键对话内容（涉及第三人信息）由独立 agent 交叉验证，类似 #16 MA-ToT Validator。
  3. 为工具/动作增加 solvability check：action 执行前显式判断目标是否可达，避免 silent success。
  4. 显式遗忘机制：参考 #24 综述所指"evolution 阶段缺遗忘"，引入冲突解消策略。
  5. 实验日志保留模块级追溯：每条 memory 记录"哪一步感知/推理/通信产生"，使幻觉归因成为可能。

FAQ（两问）

Q1. 本综述与之前的 LLM 幻觉综述（比如 Huang 2023 / Ji 2023）相比，有必要单独存在吗？

有，必要性非常强。原因不是"换个场景重新写一遍"，而是 Agent 引入了三种此前不存在的幻觉来源：

  • 循环结构：LLM 幻觉只看一次 forward；Agent 幻觉必须看多轮传播——需要全新的"累积"视角。
  • 外部 effector：LLM 幻觉最多是"说错"；Agent 幻觉是"做错"——后果与治理手段完全不同。
  • 多 agent 社会层：纯 LLM 不存在"通信幻觉"这一类型，本综述把它单独列出是原创贡献。

此外，传统二分（factuality / faithfulness）在 Agent 场景里没有粒度：一条错误的工具参数既不是事实性也不是忠实性问题。综述的"五阶段"分类是对旧框架的必要升级。<待实证>：是否真的是"首个 Agent 幻觉综述"有待对比 2024 年同类工作。

Q2. 工程上如果我今天就要构建一个"幻觉受控"的 Agent，应该优先抓哪几件事？

按综述的"阶段 × 成因"排序，投入产出比最高的三件事：

  1. 工具层最先做：Execution 幻觉最容易检测也最容易修——标准化工具文档（成因 #6）、加 solvability check（成因 #9）、工具调用后强制验证返回值（避免 silent success）。这一层改造成本低但直接消灭"最有物理后果"的一类幻觉。
  2. 记忆层加冲突消解：参考 #06 Memori 的 "overwrite / merge / ignore" 三选一，以及 #20 A-MEM 的关联网络，避免错误记忆被反复召回。显式遗忘比"永远 append"安全得多。
  3. 反思层加自验证：在 Reflection 写入前强制一轮 self-check，对应综述"Self-verification"分支。这是唯一能阻断"Perception → Memory → Reflection"污染闭环的点。

不建议优先做的：通信协议标准化（成因 #17）、causal learning（范式改进）——这些对研究有价值，但对当前 agent 产品的幻觉消除效果有限。先做"能检测的"，再做"能预防的"。
