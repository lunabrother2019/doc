一句话定位：从"压制幻觉"转向"能力增强"的应用型三路径综述

绝大多数早期幻觉工作走的是 "抑制/惩罚" 思路：对模型参数做正则化、对输出做过滤、对训练做 RLHF 反向引导。这类方法的副作用是——幻觉和创造力源自同一生成机制，压一点幻觉就压一点创造力。本综述明确反对这条路，主张走 "能力增强"：

本综述的核心主张（原文精炼）

"Instead of modifying model architectures or applying additional regularization, they strengthen LLM reliability through verifiable knowledge grounding and logical consistency constraints."
—— 不改模型，改"使用模型的方式"：给它接真知识（RAG），给它加结构化思考（Reasoning），给它配自查闭环（Agentic）。

2

三路径总览：知识型 / 逻辑型 / 复合型幻觉各对一药

本综述最关键的"分类学"贡献：把幻觉类型与缓解路径 一一对齐——不是"所有方法治所有幻觉"，而是不同药治不同病。

路径 ①

RAG Grounding（知识接地）

针对 Knowledge-based Hallucination：内部知识错误或外部信息不足。解法——在生成时从外部知识源检索真事实，把输出"钉在"可追溯的证据上。

→
路径 ②

Reasoning Enhancement（推理强化）

针对 Logic-based Hallucination：事实对但推理链断。解法——结构化思考（CoT）、工具接地（Tool-Augmented）、符号化验证（Symbolic）。

→
路径 ③

Agentic Self-Verification（动态自验证）

针对 Composite Hallucination：知识错 + 推理错交织。解法——自主 Agent 动态调度检索与推理循环，在冲突时触发修正。

2.1 三类幻觉 × 三路径 对应表

幻觉类型根因缓解路径核心机制典型评测
Knowledge-based内部知识过时/缺失/混淆RAG Grounding外部知识库 + 检索 + 融合TruthfulQA, RAGTruth, FreshQA
Logic-based事实对但推理跳步/矛盾Reasoning EnhancementCoT 显式化 / 工具接地 / 符号验证BIG-bench, PrOntoQA, LogicBench
Composite两者交织跨模块传播Agentic Self-VerificationAgent 动态调度 + 迭代修正闭环AgentBench, L-MARS, InfoDeepSeek
为什么这种分类比"factuality/faithfulness"更有工程价值

传统二分法 描述症状；本综述的三分法 指向处方。如果你的 Agent 回答"爱因斯坦 2020 年去世"——这是知识型幻觉，上 RAG；如果回答"因为 A 所以 B，因为 B 所以 not A"——这是逻辑型幻觉，上 CoT + Symbolic 验证；如果两者兼有，用 Agent 把两个工具串起来。处方化使综述真正可用。

3

每条路径的代表工作与机制

3.1 路径 ① RAG Grounding：三阶段流水线

综述把 RAG 拆成三个可独立优化的子阶段，每个阶段都有自己的幻觉风险与治理方法：

Pre-retrieval（检索前：理解意图）

把用户原始 query 转成更容易命中的形式。代表：Query Rewriting、RQ-RAG（refinement / decomposition / disambiguation 三种自改写）、多轮对话澄清、检索反馈（第一轮结果反过来再改 query）。

Retrieval（检索中：找回对的证据）

稀疏 / 稠密 / 混合检索的正确组合。代表：Hybrid Retrieval (Blended RAG) lexical + semantic 信号融合 <待实证>、GraphRAG / GNN-RAG 把知识图谱纳入检索、多粒度（句/段/文档级）、Reranking 精排、WebGLM / DeepResearcher / VisRAG（跨模态）。

Post-retrieval（检索后：融合与冲突消解）

多片段整合并处理冲突。代表：SELF-RAG（reflection tokens 决定何时引用）、LongLLMLingua（上下文压缩，避免 lost-in-the-middle）、中间层知识注入（事实保真优于简单拼 prompt）、traceability 证据链。

3.2 路径 ② Reasoning Enhancement：三条互补子路线

子路线 A：Chain-of-Thought（结构化思考）

让模型把隐式推理 外显 成步骤，每一步可被审查。代表：REFINER（迭代 refine）、Dynasor-CoT（动态调度深度）、AdaCoT / D-CoT、多路径投票。详见 #07 CoT / #11 ToT。

子路线 B：Tool-Augmented Reasoning（工具接地）

把算术、事实查询、代码执行 外包给工具。代表：ReAct（思考+行动交替，动作绑定真实观测）、Toolformer（自监督学会调工具）、PoT（推理变代码+解释器执行）、ANSWERED <待实证>。详见 #08 ReAct。

子路线 C：Symbolic Reasoning（符号化验证）

把自然语言命题 翻译成形式逻辑，用规则引擎得到 可证伪 结论。代表：Faithful CoT、SymbCoT、ChatLogic / Logic-LM（LLM 生成逻辑表达式 + 外部 solver）。三路线中最"硬"的一路——适用面窄但正确性有数学保证。

3.3 路径 ③ Agentic Self-Verification：动态编排

前两条路径相对静态：RAG 固定流水线，Reasoning 固定模板。第三条路径的新意在于——让 Agent 自己决定何时检索、何时推理、何时回退、何时验证。这是对复合幻觉（既缺知识又推理错）的正面解法。

Agentic 路径的三个核心机制
  • Dynamic Dispatch：根据任务需要动态选择"查还是算"——事实题调 RAG，推理题调 CoT，混合题交替。
  • Iterative Loops：推理与检索冲突时触发新一轮修正（Reflexion 风格），而不是一次性输出。
  • Cross-Verification：多 agent 互为验证者（类似 #16 MA-ToT Validator）。

代表系统：

  • Agent-UniRAG：统一 Agent 架构动态调度 RAG
  • Agentic Reasoning：把推理拆成工具集，agent 自行组合
  • MA-RAG（Multi-Agent RAG）：多 agent 分工 retrieve/reason/verify
  • HM-RAG（Hierarchical Multi-Agent RAG）：层级化 agent 组织 <待实证>：层级组织细节需查原文

#40 综述把 Agent 幻觉拆成 5 阶段 × 18 成因——它告诉我们"会在哪儿出问题"。本篇（#41）给出"出了问题该怎么办"。两篇合起来才构成完整的幻觉治理手册。

配对使用的直接价值

工程上遇到 Agent 出错时的决策流程：
Step 1（用 #40）— 先定位错在哪个阶段（推理/执行/感知/记忆/通信）、哪一条成因。
Step 2（用 #41）— 按路径对照表找解药（RAG 型 / Reasoning 型 / Agentic 型）。
Step 3— 从该路径的代表方法里挑一个最低成本的先上。"症状 → 分类 → 药物" 是每一套医生手册的标配。

4.2 本篇比 #40 更强的一点：可操作性

  • #40 偏学术：把问题分类得极细（18 成因），但对"怎么修"只是枚举，没有优先级。
  • #41 偏工程：三路径按"问题性质"分类，每条都给代表系统与落地工具箱。真的可以对着做选型。
  • 作者立场也不同：#41 直言"完全消除不可能"，强调 trade-off（效率 vs 创造力 vs 可靠性），这是应用工程师更熟悉的语言。

对小镇/仿真的应用：三路径如何减少 agent 行为失真

把三路径放回斯坦福小镇/用户仿真场景，可以非常清楚地对应到具体改造点。#40 综述在同主题下给出了"链 1/2/3"三种污染模式，本篇则给出对应"解药"。

5.1 三条污染链 × 三路径解药

小镇污染链（#40）病灶#41 路径改造
链 1：Perception → Memory → Reflection感知失真 + 记忆固化Agentic Self-VerificationReflection 写入前 self-check：检查是否有 memory 支撑（SELF-RAG reflection token）
链 2：Communication → Memory → Communication多 agent 谣言传播Multi-Agent Validator对话引入 Validator agent（MA-RAG），用公共知识库核对第三方信息
链 3：Planning → Execution → Memorysilent success 工具幻觉Reasoning (Tool-Augmented)ReAct 接地：action 必须返回真观测，不让 LLM 自填

5.2 一个改造后的 Smallville 架构草图

① 给 Memory Stream 加 RAG Grounding

当前小镇的记忆检索是 0.5·rec + 0.3·imp + 0.2·rel 向量加权。按本综述，单纯稠密检索会召回"看起来相关但错"的记忆。改造：引入 Hybrid Retrieval（BM25 + dense + reranker），并为每条 memory 保留来源（哪一次感知/对话写入），使 traceability 可审计。

② 给 Plan/Reflection 加 Reasoning Enhancement

当前 Reflection 是一次 LLM 调用生成高阶洞察，没有 CoT 显式化也没有验证。改造：让 Reflection 走 CoT（每一步引用具体 memory id），写入前用 Symbolic/Logic 风格检查（是否所有前提都有 memory 支持）。相当于给反思装一个证据审计员。

③ 给 Inter-Agent 对话加 Agentic Self-Verification

当前居民对话直接进入对方 memory。改造：每条涉及第三方的 "事实性陈述" 由独立 Validator agent 核对（MA-RAG 风格），验证通过才写入；不通过则标记为"听说"（低 importance）。这直接打断 Communication → Memory → Communication 的污染闭环。

本综述对小镇 最有价值的启示：小镇的设计初衷是 "高生成力"（让居民能涌现出有意思的社交），所以它故意少做验证。但做 用户行为仿真 时，目标反过来——需要仿真结果"可信"而非"有意思"。这时把本综述的三路径全部接入才合理：RAG 接真世界知识、CoT 管推理透明、Multi-Agent Validator 管谣言治理。
换句话说：Generative Agents 架构天生更偏创造力，要做可信仿真必须改造成三路径都打开的版本。这是把小镇从"有趣的 demo"升到"可信的实验平台"的必经路径。
落地优先级建议（给仿真研究者）
  1. 最先做 RAG 接世界知识：让居民对"天气""新闻""本地事件"的感知接入真实数据源，而不是任由 LLM 编造。
  2. 其次做 Tool-Augmented Action：让 walk_to / eat / talk 等动作返回真实结果（即便只是确定性规则引擎），消除 silent success。
  3. 最后做 Multi-Agent Validator：成本最高但对社交模拟最关键——没有它，谣言传播实验结果不可信。
  4. Reflection 加 self-check 是高 ROI 小改：改动量很小但能堵住 Perception→Memory→Reflection 污染闭环。

FAQ（两问）

Q1. 三路径是"三选一"还是"三合一"？实际部署应该怎么选？

综述明确建议是 三合一，但按幻觉类型 有侧重：

  • 知识密集型应用（医疗问答、法律咨询、新闻摘要）：重心放 RAG，推理和 Agentic 是辅助。
  • 推理密集型应用（数学、代码、规划）：重心放 Reasoning Enhancement，RAG 偶尔补知识。
  • 开放探索/多步任务（DeepResearcher、多跳问答、仿真 agent）：必须上 Agentic Self-Verification 串起前两者。

关键是不要"一条路径走到黑"。综述指出一个常见误区：过度依赖 RAG 会让"检索失败本身变成新的幻觉源"——知识库里没答案时，模型仍会强行"编造"基于检索结果。这时就必须用 Agentic 的 solvability check 提前识别并告知"不知道"。<待实证>：具体在哪些任务上这种退化最严重，综述未给统计。

Q2. 本综述声称"幻觉完全消除不可能"——这对做 Generative Agents 仿真意味着什么？

这个立场对仿真研究者非常关键，有两层含义：

第一层（工程层）：不要追求"零幻觉 agent"，追求 可控幻觉。具体做法是把三路径装上，并且对不同场景启用不同组合——事实查询严格走 RAG，创造性对话放松到纯生成，中间态用 Agentic 动态切换。

第二层（方法论层）：仿真实验要 区分"涌现行为"与"模型幻觉"。小镇里居民"编造谣言并扩散"在人类社会里真实存在——但在 LLM agent 仿真中，它可能是模型幻觉被误认为社会涌现。没有本综述的三路径做对照组，你没法证伪。

推荐做法：做对照实验——同一 scenario 跑两次，一次开启所有三路径（guard on），一次关闭（guard off）。只有两者差异对应的行为才是 "真正由 LLM 幻觉导致的失真"；两者一致的行为才是可信的涌现仿真结果。这实际上是把本综述从"工程方法"升级为"仿真研究方法论"。
