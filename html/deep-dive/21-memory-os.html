动机与类比:为什么 LLM 记忆需要一个 OS?

LLM Agent 的记忆管理最终会撞上一个老问题:容量远大于即时可访问的"工作集"。这正是 1960 年代计算机 OS 面对的问题 —— 内存容不下所有程序,需要分级存储 + 调度淘汰。MemoryOS 的核心主张是:LLM Agent 也需要一个完整的"记忆操作系统"。

三级存储架构

① Short-Term Memory — 短期记忆

职责:保存当前对话的直接上下文,类似 CPU 寄存器或 L1 cache。

内容:最近几轮 (user, assistant) 对话原文,按 FIFO 队列组织。

淘汰:超过容量时,最老的对话被"降级"到中期记忆。

② Mid-Term Memory — 中期记忆

职责:保存最近若干天 / 若干会话的话题级别信息,类似 RAM。

内容:由短期记忆降级而来的对话被按话题聚合、摘要化;保留时间戳和来源。

淘汰:分段分页策略 —— 话题以"页"为单位,冷门话题页整页淘汰到长期记忆。

③ Long-Term Personal Memory — 长期记忆

职责:持久化的用户画像 + 人设事实 + 跨会话偏好,类似硬盘。

内容:从中期记忆提炼出的"稳定事实"("用户喜欢 Python"、"用户是远程工作者"),不再是原始对话。

淘汰:原则上不淘汰 —— 这是 Agent 对用户的长期理解基础。

为什么正好是 3 级?
这不是任意选择。它对应了人类认知心理学的"感觉记忆 / 短时记忆 / 长时记忆"三分,也对应了计算机存储层级的"寄存器 / RAM / 磁盘"。三级架构在成本和性能之间找到了一个 本地最优:少一级会丢失中间抽象,多一级会增加调度开销。

调度策略:两种降级机制

MemoryOS 的技术核心是短→中和中→长这两个降级通道。论文为它们设计了不同的策略,这是 OS 类比最精致的部分。

短期 → 中期:Dialogue-Chain FIFO

原则:"对话链 FIFO",即不是按单轮淘汰,而是按对话话题的起止边界淘汰。

  • 短期记忆监测到话题切换(用户提了完全不同的问题)
  • 之前那段对话链作为一个"chunk"被整体降级到中期记忆
  • LLM 生成对话链摘要 + 提取关键信息

这样做的好处是:摘要保持话题内的完整性,而不是随意切断上下文。类似 OS 里的 "working set"概念 —— 同一话题的对话应该整体进退。

中期 → 长期:Segmented Page Organization

原则:"分段分页组织",把中期记忆按主题分"段",每段内再按时间分"页"。

  • 每段 = 一个稳定主题(工作 / 家庭 / 兴趣爱好)
  • 每页 = 一次相关会话的摘要
  • 淘汰时:冷门页被进一步提炼,抽出稳定事实写入长期记忆,原页丢弃

这类似 OS 的 page-out 机制,但多了一个"提炼"步骤 —— 不是整页保存到磁盘,而是从中抽取 insight。

关键差异:有损 vs 无损
传统 OS 的分页是无损的 —— 磁盘上保存的页和 RAM 里的页逐字节一致。MemoryOS 的降级是有损的 —— 每次降级都经过 LLM 摘要/提炼,丢失细节但保留要义。这是设计选择:记忆 Agent 不需要精确还原,需要的是"我记得重点"。

四大核心模块

论文把系统功能分成四个正交模块,对应 OS 里的内核服务:

模块 OS 类比 职责
Memory Storage 文件系统 三级存储的底层数据结构 + 持久化
Memory Updating 页面调度器 执行短→中、中→长的降级;触发摘要/提炼
Memory Retrieval 缓存查找 + 页错处理 按 query 跨三级检索;命中则返回,未命中则回源长期记忆
Memory Generation 系统调用 / 响应 把检索结果注入 LLM prompt,生成用户可见的响应
模块化的工程价值
这四个模块各有明确接口,可以独立替换。想换检索算法?只改 Retrieval。想换摘要策略?只改 Updating 里的降级逻辑。这种正交分解是 OS 思想带给 LLM 记忆系统的真正红利 —— 让不同实验室的改进可以组合。

实验结果

论文在 LoCoMo(Long Conversation Memory)基准上用 GPT-4o-mini 做评测。LoCoMo 是一个专门为"长对话下的记忆能力"设计的 benchmark,测试 Agent 能否在几十轮对话后准确回忆早期信息。

指标 提升(相对基线) 说明
F1 分数 +49.11% 回答准确性的 token 重叠度,最核心指标
BLEU-1 +46.18% 生成质量的 n-gram 评价
测试模型 GPT-4o-mini
如何解读这些数字

49% 的 F1 提升听起来很大,需要注意两点:

  1. 这是相对无记忆管理的 GPT-4o-mini 的相对提升。基线本身在长对话上表现很差(LoCoMo 的设计就是让无记忆 Agent 崩溃),因此百分比空间大。
  2. 与其他记忆系统(如 A-MEM、Memori)的直接对比需要看原论文的详细表格,abstract 只披露了相对基线的改进。

与斯坦福小镇的关联

Smallville 的 Memory Stream 在概念上对应 MemoryOS 的单一存储层 —— 所有记忆都在一个池子里,通过打分 + top-k 访问。这在 25 个 Agent / 2 天尺度下没有问题,但如果把小镇的时间尺度拉到几个月甚至几年,Memory Stream 必然会崩溃。

MemoryOS 提供了一个明确的扩展路径:

Smallville 组件 MemoryOS 对应改造
Memory Stream(扁平日志) 拆为短期 / 中期 / 长期三级
Reflection(周期批处理) 变成降级通道的自然副产物(每次降级都做摘要 = 增量反思)
三分打分(recency × importance × relevance) Retrieval 模块优先查短期 → 中期 → 长期,按层命中
Planning 从记忆中拉上下文 Generation 模块跨层拼接 prompt
MemoryOS 可以视为 Smallville Memory Stream 的工业化版本:把原本耦合在一起的"存储 + 检索 + 反思"拆成正交模块,用 OS 调度策略替代朴素打分。它的代价是系统复杂度显著提升(三级数据结构 + 两种降级通道),回报是长时运行下的记忆质量和成本都可控。如果你在做 Agent 长期记忆系统的工程实现,MemoryOS 比 Memory Stream 更接近"可直接采纳"的参考架构。而如果你做研究,A-MEM 的图结构和 MemoryOS 的分级调度可以组合 —— 它们解决的是不同维度的问题(前者管语义关联,后者管容量调度)。
